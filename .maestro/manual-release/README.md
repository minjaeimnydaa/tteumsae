# 수동 출시 검증·촬영용 흐름

이 폴더는 `.maestro/config.yaml`의 기본 `flows/*.yaml`에서 제외한다.
실제 운영 장소·기존 로그인/저장 상태·특정 시각을 전제로 한 출시 QA와 캡처 도구이며,
전체 폴더를 일반 smoke처럼 연속 실행하지 않는다.

기존 `.maestro/flows/`에도 `gps-denied-kakao.yaml` 등 자동 위치 전용 흐름이 남아 있다.
따라서 기본 전체 폴더 실행이 수동 APK에 호환된다는 뜻이 아니며, 수동 검증은 아래
준비 조건을 갖춘 파일을 명시적으로 선택한다.

- `manual-release-input`: 출발지 수동 입력·추천 준비.
- `manual-release-detail`, `manual-release-saved-settings`: 준비된 결과/저장 화면에서 왕복 확인.
- `manual-release-login-handoff`: 카카오 로그인 화면까지만 연다. 계정 동의는 직접 확인한다.
- `manual-release-notices-and-tourism`: code32의 기존 카카오 로그인과 순포해변 저장 상태가 필요하다.
- `manual-tourism-*`: 2026-09-13 관광 예시 촬영. 특히 capture는 06시대 도착 마감과
  해당 시각의 추천에 의존하므로 다른 시간에 장소가 빠지는 것을 앱 오류로 판정하지 않는다.

각 파일의 주석과 시작 조건을 읽고 한 파일만 명시적으로 실행한다. 실행 결과는
`docs/08_QA_AND_KNOWN_ISSUES.md`와 Git 제외 `tmp/release-qa-final-20260913/`에 구분한다.
기존 알림을 관찰 중일 때 앱 강제 재시작·새 경로 검색·다른 장소 선택을 하지 않는다.
이는 알림 취소나 재예약을 유발할 수 있다. 사용자 계정/저장 데이터 삭제는 하지 않는다.

## code34 주소 검색·연속 지도/목록 시트 회귀

`code34-address-sheet.yaml`은 **0.13.1 / code34 수동 APK**와 주소 검색이 배포된
백엔드에서만 실행한다. 기존 파일이나 이전 APK의 기준을 대체하지 않는다.
2026-09-13 최종 **30E0 / 수동·자동227개** 빌드의 깨끗한 재실행에서 **1/1 통과,73초,캡처8장**을 확인했다.
증거는 `tmp/ux-v34-20260913/final30-clean-run/2026-09-13_063338/` 아래다.
첫 최종 실행은 목적지 검색 공급자 응답 지연으로58초 실패했으며 같은 검색 재시도로 복구했다.
그 실패를 통과로 지우지 않는다. 이전 E55 후보의75초 통과와 아래 중간 후보73초 통과도 별도 실행이다.

앞선 06시대 잠금 해제 실기기의 중간 code34 후보에서도 **1/1 통과, 73초, 캡처8장**을 확인했다.
증거는 `tmp/ux-v34-20260913/final-address-sheet/2026-09-13_060036/` 아래에 있다.
이 실행은 자동 테스트220개를 통과한 중간 후보이며 이후 묶음 핀 보완본의 최종 통과 기록이 아니다.

### 시작 조건

- 폰을 연결하고 잠금 해제한다. 앱이 이미 전면의 **HOME**에 있어야 하며 첫 안내 팝업은
  직접 닫아 둔다. 이 flow는 앱을 강제 재시작하거나 다른 화면에서 임의로 뒤로 가지 않는다.
- HOME에서 새 검색을 열면 기존 경로 입력·선택 필터가 초기화되고 도착 마감은 현재부터
  약 1시간 뒤로 설정된다. 고정된 오전 시각이나 과거 촬영 상태를 사용하지 않는다.
- **알림 실수신 검증 중에는 실행 금지.** 새 검색은 기존 경로 알림을 취소할 수 있다.
  로그인·찜·앱 데이터·권한은 변경하지 않고 새 알림이나 외부 길안내도 시작하지 않는다.
- 인터넷·Kakao 지도·검색·추천 서버가 정상이어야 한다. 주소 검색이 아직 배포되지 않은
  서버나 code33 이하에서는 `주소` 후보/새 시트 버튼을 찾지 못하는 것이 정상이다.
- 글자 크기·화면 크기에 따라 입력 필드가 가려져 있으면 우선 화면을 직접 확인한다.
  보이지 않는 항목에 좌표를 추측하거나 과거 UI의 `index: 1`을 임의로 넣어 통과시키지 않는다.

### 검증 범위와 해석

1. HOME → 새 검색 → `강릉시 강릉대로 33` 입력 → 정규 도로명 주소와 `홍제동 1001`
   지번 확인 → **주소 자체 선택**. 입력값과 검색 결과가 겹치지 않도록 정규 전체 주소를 선택한다.
2. `강릉 경포대` 입력 → 관광지 `경포대` 선택 → 기본 약 1시간 뒤 도착 마감으로 추천.
   관심 필터는 따로 켜지 않아 시간대별 관광지 후보 부족과 시트 회귀를 섞지 않는다.
3. 기본 중간 시트 → `지도 크게 보기` → `목록 펼치기` → `지도와 목록 함께 보기`.
   다시 목록을 펼친 뒤 시스템 Back이 입력 화면이 아니라 중간 시트로 돌아오는지 확인한다.
4. 지도 크게 보기 버튼의 enabled 상태와 펼치기/중간 복귀 접근성 이름을 실제로 검사한다.
   검색 결과 개수나 특정 경유지는 시각·교통·운영 데이터에 따라 달라지므로 고정하지 않는다.

8개 스크린샷은 `code34-01-home`부터 `code34-08-results-back-balanced`까지 생성한다.
실행자는 이미지에서 주소 읽기, 지도·시트의 연결, 핸들/버튼 가림과 지도 로고 여백을 확인한다.
명령 통과만으로 핀 선택·목록 읽던 위치 유지·드래그 제스처·선택 버튼 스타일·상세 왕복까지
검증됐다고 기록하지 않는다. 이 항목은 별도 실기기 확인이 필요하다.

별도 수동 조작에서 같은 카드의 선택 전후 버튼, 핀 선택에 따른 맞는 카드 노출, 목록/상세 왕복과
지도/목록 스크롤 유지를 확인했다. 글자2.0/density540(약320dp)의 헤더·행동 복원과 선택/상세
버튼 세로 배치도 확인하고 원래 글자0.9/density450으로 복구했다. 이는 위 flow의 자동 검증 범위와 구분한다.
추가 묶음5곳 MAP→BALANCED 검사에서 핀 가림을 발견했으므로 `final-cluster-settled.png`를
통과 이미지로 사용하지 않는다. 이후E55에서는 하단 가림이 해소됐지만 상단 스포츠 핀 겹침을 발견했다.
최종30E0의 `final30-cluster-settled`·`four`·`three`와 중간 시트를 별도 검수해 구성원 몸통·꼬리의
시트 위 노출과 전체 경로 버튼과의 겹침 해소를 확인했다. 해당 수동 검사는 이 flow 자체의 자동 범위가 아니다.
E55에서 핀·상세 복귀, 알림 켠 상태 왕복 유지 후 끄기, 목록→지도→목록 읽던 위치 유지도 확인했다.
큰 글자는220개 후보 검사다. 최종30E0의 모든 화면·글자 크기·알림 실수신까지 새로 검사했다고 쓰지 않는다.
원래 화면 유지 설정0·글자0.9·density450 복구 기록은 이전 검증 시점 기록이다.
공개APK는06:39 code34로 교체·재다운로드 해시 확인했다. 포털APK32·기존11시검토묶음33은 유지하며,
최종 신청은 11시 검토 후 새 사용자 지시까지 보류한다. 자료 차이는 `docs/28_CODE34_REVIEW_ADDENDUM.md`를 따른다.

초기 화면이 다르거나 주소/지도 공급자가 실패하면 자동으로 재검색·임의 탭하지 않고 실패에서
멈춘다. 실제 UI와 네트워크 상태를 확인한 뒤 HOME으로 직접 돌아와 처음부터 다시 실행한다.
실행은 이 파일만 지정하고 캡처 출력은 Git 제외 QA 폴더로 설정한다.
