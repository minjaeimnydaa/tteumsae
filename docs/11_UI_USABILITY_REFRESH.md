# UI 사용성 개선 기준

기준일: `2026-08-28`
대상: Android 활성 흐름 `HOME → LOCATION → LOADING → RESULTS → DETAIL`과 장소 탐색,
설정, 프로필

## 1. 목표

현재 제품의 흰색·연회색 바탕, 검정 타이포, 빨간 포인트, 둥근 카드 중심 디자인 무드는
유지한다. 이번 변경은 기능이나 추천 계약을 확장하지 않고 입력 단계, 상태 피드백,
정보 우선순위와 팝업의 레이어 구분을 개선한다.

핵심 원칙은 다음과 같다.

- 자주 쓰는 입력은 별도 화면이나 확인 버튼 없이 현재 맥락에서 끝낸다.
- 로딩, 완료, 실패 상태를 정적인 장식이 아니라 시간에 따라 변하는 피드백으로 표현한다.
- 팝업은 스크림, 그림자, 테두리와 등장 모션으로 배경과 분리한다.
- 없는 정보와 추정 정보는 표시하지 않는다.
- 지도와 추천 목록은 동시에 비교할 수 있어야 한다.
- 빨간색은 선택, 주요 행동과 실제 경고에 집중한다.

## 2. 우선순위 결정

### P0 — 정보 신뢰

- 장소 상세의 공백, `null`, 문자열 `"null"`을 사용자에게 노출하지 않는다.
- 장소 유형만 보고 실내·야외, 주차, 반려동물 가능 여부를 추정하지 않는다.
- 값이 없는 방문 정보는 반복적인 `정보 확인 필요` 행 대신 하나의 안내로 대체한다.

### P1 — 핵심 흐름

- LOCATION의 아날로그 시간 다이얼과 별도 확인 단계를 제거한다.
- 도착 마감은 화면 안의 24시간제 시·분 휠로 즉시 반영한다.
- 마감은 기본값을 제공하고 `오늘` 또는 `내일`을 명시한다.
- LOADING은 진행 항목이 순차적으로 로딩에서 체크로 바뀌고, 성공 시 완료 상태를 짧게
  보여준 뒤 RESULTS로 전환한다.
- 첫 안내와 로딩 카드는 공통된 강한 모달 레이어를 사용한다.
- RESULTS의 추천 목록은 접을 수 있는 바텀시트로 제공해 지도를 가리지 않는다.
- 교통 재확인 진입점은 하나만 두고 마지막 계산 시각을 표시한다.

### P2 — 보조 화면

- 장소 탐색 로딩은 `스팟 (0)` 대신 스켈레톤과 `불러오는 중` 상태를 표시한다.
- 이미지가 없는 장소는 카테고리별 플레이스홀더로 구분한다.
- 실제 메뉴가 아닌 정렬 토글에서 드롭다운 화살표를 제거한다.
- 설정의 계정 카드는 압축하고 계정 삭제의 시각적 우선순위를 낮춘다.
- 추천에 사용하지 않는 연령대와 성별 입력은 프로필 화면에서 제거한다.

## 3. 화면별 확정 동작

### HOME·첫 안내

- 지도, 목적지 검색, 현재 위치 버튼과 하단 탭 구조는 유지한다.
- 첫 안내 카드는 높은 그림자와 얇은 테두리, scale/fade 등장 모션을 사용한다.
- `오늘 하루 보지 않기`와 닫기 정책은 유지한다.

### LOCATION

- 출발지와 목적지 검색 동작, 위치 권한 fallback과 선택 필터는 유지한다.
- 도착 마감은 `[시] : [분]` 세로 휠을 항상 노출한다.
- 24시간제를 사용하고 선택 결과 위에 `오늘` 또는 `내일`을 표시한다.
- 휠 변경은 즉시 `arrivalDeadlineEpochMillis`에 반영하며 별도 확인 버튼을 두지 않는다.
- 필터 제목은 실제 의미에 맞게 `들르고 싶은 곳 · 선택`으로 표현한다.

### LOADING

- 지도 위에 반투명 검정 스크림을 적용한다.
- 흰 카드에는 강한 elevation과 테두리를 사용한다.
- 진행 문구는 서버의 세부 진행률이라고 오해하지 않도록 사용자 관점의 일반 문장으로 쓴다.
- 응답이 준비되면 전체 항목을 체크하고 `틈새를 찾았어요`를 잠깐 보여준 뒤 이동한다.
- 실패와 뒤로가기는 기존 취소·복귀 계약을 유지한다.

### RESULTS

- 지도 핀 `+N분`, 한 곳 선택·재탭 해제, 직행 CTA 계약은 유지한다.
- 하단 추천 영역은 드래그 가능한 바텀시트로 변경한다.
- 추천 카드는 기본 흰색, 선택 카드만 붉은 소프트 배경과 테두리를 사용한다.
- 카테고리와 운영상태를 비교 정보로 보강한다.
- 선택형 알림은 선택 카드 안에서 출발 권장 시각과 함께 제공한다.
- 상단 재확인 아이콘 하나만 유지하고 마지막 계산 시각을 함께 표시한다.

### DETAIL

- 주소를 장소명 바로 아래에 배치한다.
- 분 단위 값은 가능하면 `N시간 M분`으로 읽기 쉽게 표시한다.
- 방문 정보는 실제 값이나 명시적 태그가 있는 항목만 표시한다.
- 하단 보조 문구는 추가 이동시간 반복 대신 출발 권장시각을 우선한다.

### 장소 탐색

- 초기 로딩은 2열 카드 스켈레톤을 사용한다.
- 카테고리별 플레이스홀더 색과 이름으로 이미지 부재 상태를 구분한다.
- 정렬 토글은 `추천순`과 `이름순`처럼 실제 동작을 그대로 표현한다.

### 설정·프로필

- 로그인 제공자와 사용자 정보는 압축된 계정 카드로 표시한다.
- 프로필 관리는 계정 행 전체를 눌러 진입할 수 있게 한다.
- 프로필은 현재 제품에 실제로 쓰이는 닉네임만 편집한다.
- 변경이 없으면 저장 버튼을 비활성화하고 기존 연령대·성별 값은 수정하지 않는다.

## 4. 비범위

- 추천 알고리즘, 최소 체류 15분, 안전여유 10분과 V1 API 계약 변경
- 복수 경유지, 자동 실시간 재조회, 지오펜스
- 저장 장소의 클라우드 동기화
- 새로운 색상 체계나 전면적인 브랜드 리디자인
- Navigation Compose나 앱 전체 구조 전환

## 5. 검증 기준

- 기존 Android 단위 테스트가 모두 통과한다.
- 새 표시 정책은 `null`과 문자열 `"null"`을 모두 숨기는 테스트를 갖는다.
- `lintDebug` 오류가 없고 `assembleDebug`가 성공한다.
- 실기기에서 시간 휠 즉시 반영, 로딩→완료 모션, 결과 바텀시트, 상세 정보 fallback,
  장소 탐색 로딩과 프로필 저장 활성 조건을 캡처한다.
- 지도, 추천, 한 곳 선택, 카카오맵 안내와 알림 계약은 회귀하지 않는다.

## 6. 적용 결과

2026-08-28에 이 문서의 P0~P2 항목을 Android 코드에 일괄 반영했다. SM-F776N
(Android 17, API 37) release 빌드에서 다음을 확인했다.

- 인라인 시·분 휠의 탭·스와이프와 `오늘/내일 HH:mm까지` 즉시 반영
- 지도 스크림, 카드 그림자·테두리, 순차 로딩→체크 전환
- 지도와 함께 보이는 결과 바텀시트, 계산 시각, 카테고리·운영상태
- 상세 주소 우선 배치, 읽기 쉬운 시간, `null` 제거와 단일 fallback
- 첫 안내 팝업의 배경 분리, 장소 카테고리 플레이스홀더, 계정·프로필 단순화

단위 테스트는 표시 정책의 공백·`null`·문자열 `"null"`과 시간 포맷을 포함한다. 자동
검증 수치와 APK 정보는 [QA 문서](08_QA_AND_KNOWN_ISSUES.md)를 단일 기준으로 삼는다.

## 7. 지도 중심 흐름 보완 — 2026-08-29

실기기 검토 뒤 HOME, LOCATION, RESULTS의 지도 맥락을 다음처럼 보완한다.

- HOME의 작은 목적지 검색 카드는 별도 흰 화면으로 전환되지 않고, 같은 지도 위의
  드래그 가능한 입력 패널로 확장된다.
- 입력 패널은 확장·부분 접힘 두 상태만 사용한다. 손잡이를 내리면 키보드를 닫고 지도
  조작을 허용하되 검색어와 결과는 유지한다. 패널 전체 스와이프는 검색 목록·시간 휠과
  충돌하므로 사용하지 않는다.
- 출발지·목적지는 글자형 대형 캡슐 대신 서로 구분되는 작은 플래그 아이콘으로 표시한다.
- 줌아웃에서 가까운 후보는 `N곳` 클러스터로 묶고, 클러스터를 누르면 포함 후보가
  분리될 때까지 확대한다. `+N`은 추가 이동시간 의미와 충돌하므로 개수 표시에 쓰지 않는다.
- 후보를 선택하면 해당 위치로 부드럽게 확대하고 변경된 경로를 보여준다. `전체 경로`
  보조 버튼으로 출발지부터 목적지까지 다시 맞출 수 있다.
- 로딩 카드의 상단 돋보기 무한 회전은 제거한다. 정적 지도 아이콘과 단계별 로딩→체크,
  최종 완료 체크만 유지한다.

### 적용·실기기 확인

HOME 지도는 재생성하지 않고 같은 컴포지션 위에서 입력 패널만 나타나도록 구현했다. SM-F776N
(Android 17, API 37) release 빌드에서 입력 패널의 확장→부분 접힘→재확장, 검색어 유지와
지도 조작을 확인했다. 결과 화면에서는 작은 출발·목적지 플래그, `3곳` 클러스터,
클러스터 탭 후 개별 `+N분` 핀 분리, 후보 선택 자동 확대와 `전체 경로` 복귀를 확인했다.
상단 로딩 표시는 회전 돋보기 없이 정적 지도 아이콘→완료 체크로 동작한다.

클러스터의 근거리 묶음·최대 줌 개별 표시·원거리 분리 정책을 단위 테스트로 추가했다.
전체 자동 검증 결과는 123/123 통과, lint 오류 0, debug·release APK 패키징 성공이다.

## 8. 검색 패널·후보 상호작용 보정 — 2026-08-29

추가 실기기 피드백을 반영해 검색 패널과 결과 지도 사이의 위치·선택 관계를 보정했다.

- 검색 패널은 상태 표시줄 inset을 중복 적용하지 않고 상단에 지도 여백을 남긴다. 확장
  상태의 손잡이는 둥근 모서리 아래에 완전히 노출되며, `110dp` 부분 접힘에서는 제목과
  설명까지만 보이고 입력 카드가 잘려 나타나지 않는다.
- 후보 묶음은 고정 미터 반경 대신 현재 줌의 Web Mercator 화면 좌표를 사용한다. 기기
  밀도를 반영한 `56dp` 반경 안의 후보만 묶으므로 같은 장소라도 줌인할수록 여러 묶음과
  개별 핀으로 순차 분리된다.
- 클러스터를 누를 때 중심을 유지하며 3단계씩 확대한다. 반복 탭으로 `N곳`에서 더 작은
  묶음, 마지막에는 `+N분` 개별 핀까지 도달한다.
- 선택 전에는 첫 후보를 임의 강조하지 않아 클러스터를 가리지 않는다. 개별 핀을 누르면
  현재 줌을 축소하지 않은 채 해당 장소를 중심으로 맞춘다.
- 선택 후보는 결과 목록의 첫 항목으로 재배치하고 목록 상태도 첫 위치에서 다시 시작한다.
  접힌 시트와 펼친 시트 모두에서 지도 핀과 대응 카드가 즉시 연결된다.

SM-F776N(Android 17, API 37) release 빌드에서 `8곳 → 3곳 → 개별 +7분 핀`의 단계 확대와
세 번째 후보 선택 후 `강릉감자옹심 강릉본점` 카드가 최상단 `선택됨`으로 이동하는 것을
확인했다. 최종 자동 검증은 123/123, 실패 0, lint 오류 0(경고 36)이며 release APK를
연결 기기에 덮어쓰기 설치했다.

## 9. 후보 묶음 경계·카메라 여백 보정 — 2026-08-29

줌 경계에서 핀이 반복 결합·분리되거나 라벨이 헤더·결과 시트에 잘리는 문제를 다음처럼
보정했다.

- 확대 중에는 `48dp`, 축소 중에는 `64dp`, 최초 상태에는 `56dp`를 묶음 반경으로 쓴다.
  같은 줌 경계를 오갈 때 바로 반대 상태로 튀지 않는 방향별 히스테리시스다.
- 한 후보가 묶음에 들어가려면 기존 모든 구성원과 반경 이내여야 한다. 양 끝은 멀지만
  중간 후보 때문에 하나로 이어지는 사슬형 묶음을 만들지 않는다.
- 후보가 있는 지도는 좌우 `72dp`, 상단 `128dp`, 하단 `300dp`를 실제 지도 패딩으로
  반영해 카메라와 지도 UI의 유효 영역을 헤더·결과 시트 사이로 제한한다.
- 묶음 탭은 포함 후보 전체를 `24dp` 추가 여백으로 맞추고, 한 번에 최대 2단계만
  확대한다. 개별 후보 선택은 줌 12로 맞춰 선택 핀과 주변 라벨이 함께 보이게 한다.

SM-F776N(Android 17, API 37)에서 장거리 `8곳`이 `7곳 + +46분`, 이후
`6곳 + 개별 핀`으로 점진 분리되는 것을 확인했다. 각 단계와 개별 핀 선택 뒤에도 선택
라벨·주변 묶음·상단 헤더·하단 카드가 서로 잘리지 않는 것을 확인했다. 전체 자동 검증은
125/125, 실패 0이고 lint 오류 없이 release APK를 연결 기기에 설치했다.

## 10. 전 화면 상용화 패스 — 2026-09-05

### 감사 근거와 범위

USB로 연결한 실기기에서 HOME, 첫 안내, LOCATION의 확장·접힘·검색·시간 입력, LOADING,
RESULTS의 미선택·선택, 추천 상세, 장소 탐색의 목록·필터·빈 상태·상세, SETTINGS,
PROFILE과 계정 삭제·캐시 확인창을 화면별로 캡처했다. 로그인 상태여서 로그인 시트는
조건부 생략했고, 저장 목록이 비어 저장 전체 삭제 확인창도 생략했다. RESULTS 오류 상태와
OAuth는 별도 호환성 범위로 남겼다. 캡처와 함께 UI 계층, 실제 버튼 흐름과 Compose 구현을
교차 확인해 한 화면의 정적인 모양뿐 아니라 진입·상태 변화·복귀가 자연스러운지도 감사
기준에 포함했다.

기존의 흰색·연회색 바탕, 검정 타이포, 빨간 포인트와 둥근 카드 무드는 유지한다. 이번
패스는 새로운 기능을 추가하는 리디자인이 아니라, 캡처에서 드러난 시스템 inset 중복,
작은 터치 영역, 불명확한 상태, 반투명 레이어와 정보 잘림을 상용 서비스 수준으로
정리하는 작업이다.

### 공통 레이아웃·상태 원칙

- 지도 화면은 지도를 시스템 영역까지 이어지는 full-bleed 배경으로 두고 Scaffold의
  content inset을 제거한다. 검색 카드·헤더·버튼 같은 실제 조작 오버레이에만 상태 표시줄과
  내비게이션 inset을 한 번 적용한다. 일반 목록·폼 화면은 Scaffold가 제공하는 안전 영역만
  사용해 inset을 중복하지 않는다.
- 지도 SDK가 준비됐다는 콜백 직후에도 타일이 덜 그려진 민트색·빈 화면이 보일 수 있으므로,
  지도 콘텐츠가 안정될 때까지 브랜드형 스켈레톤을 유지한 뒤 지도에 전환한다. 오류 상태는
  스켈레톤과 구분하고 다시 시도 행동을 제공한다.
- 주요 행·필터·취소·확인 행동은 최소 `48dp`, 핵심 CTA는 최소 `56dp` 터치 영역을
  보장한다. 큰 글자에서는 고정 높이보다 `heightIn`을 사용해 내용이 잘리지 않게 한다.
- 폰보다 넓은 화면에서는 목록·폼·모달이 화면 전체로 늘어나지 않도록 일반 콘텐츠는 약
  `640dp`, 확인 모달은 약 `420dp`의 최대 폭으로 중앙 정렬한다.

### HOME

- 목적지 검색 카드 주변에 `가는 길에 잠깐 들를 한 곳을 찾아드려요`와 같은 가치 문구를
  항상 남긴다. 첫 안내를 닫은 뒤에도 사용자가 앱이 무엇을 하는지 바로 알 수 있어야 한다.
- 현위치 버튼은 활성 상태에서 다시 눌러도 위치 표시를 지우지 않는다. 일반 지도 서비스의
  관습대로 위치를 다시 얻고 현재 위치로 재중심한다.

### LOCATION

- 비활성 CTA 위에는 출발지, 목적지, 도착 마감, 위치 확인 중 가운데 현재 부족한 조건을
  설명한다. 네트워크·지역 판별 실패는 필터 아래가 아니라 입력 제목과 필드 가까이에
  지속되는 배너로 표시한다.
- 출발지·목적지 검색에는 `48dp` 지우기 버튼과 명확한 접근성 이름을 제공하고, 선택한 값을
  수정할 때도 짧은 텍스트 영역만 누르게 하지 않는다.
- 관심 필터는 최소 `48dp`와 실제 선택 상태 semantics를 갖는다. 보이는 선택 색만으로
  상태를 전달하지 않는다.

### LOADING·공통 모달

- 로딩은 일반 Box 위에 카드를 얹는 방식이 아니라 실제 모달 Dialog로 표시해 바깥 지도와
  컨트롤의 터치를 차단한다. 사용자가 명시적으로 `검색 취소`를 선택하는 동작은 유지한다.
- 모달에는 불투명한 흰색 surface, 충분한 scrim, 제한된 최대 폭을 적용한다. 진행 단계와
  완료 전환에는 pane title, live region과 상태 설명을 제공해 TalkBack에서도 변화를 알린다.
- 첫 안내, 계정 삭제, 캐시·저장 삭제 확인창에도 같은 레이어·폭·버튼 위계 원칙을 적용한다.

### RESULTS

- 결과 바텀시트와 카드 surface는 불투명하게 합성해 지도 라벨과 워터마크가 본문 뒤로
  비치지 않게 한다. 빨간색은 선택과 주요 CTA에 집중하고 선택 카드의 강조 밀도는 낮춘다.
- 현재 교통 재확인 실패는 목록 위의 작은 문장이 아니라 눈에 띄는 경고 배너와 다시 확인
  행동으로 표시한다. 새로고침 중 상태에도 설명을 제공한다.
- 후보 순위는 바꾸지 않는다. 선택 시 안정적으로 유지한 목록 상태에서 해당 카드 위치로
  부드럽게 스크롤해 지도 핀과 목록을 연결한다. 이는 2026-08-29의 `선택 카드를 실제 목록
  선두로 재배치` 결정을 대체한다.
- 결과가 없을 때는 일반 선택 안내를 재사용하지 않고 조건 변경과 목적지 직행 행동을
  명확히 제시한다.

### DETAIL

- 최대 체류와 출발 시각은 보장값처럼 쓰지 않고 `최대 약`, `출발을 권장해요`로 표현한다.
  계산 시각과 `교통 상황이 바뀌면 달라질 수 있음`을 함께 보여 카카오맵의 재계산 결과와
  차이가 날 수 있음을 숨기지 않는다.
- 최대 체류, 늦어도 출발할 시각, 운영시간, 휴무일과 장소 설명은 2열 고정이나 말줄임표로
  자르지 않는다. 큰 글자에서도 전체 텍스트를 읽을 수 있는 세로 정보 구조를 우선한다.
- 실제 장소 소개와 경로 추천 이유를 같은 제목으로 섞지 않는다.

### 장소 탐색·저장 상세

- 장소 목록과 로딩 스켈레톤은 `GridCells.Adaptive`를 사용해 좁은 폰과 태블릿 모두에서
  카드 최소 폭을 유지한다. 필터·검색 때문에 결과가 없으면 설명만 두지 않고
  `검색·필터 초기화` 행동을 제공한다.
- 검색어 지우기, 지역 선택, 필터와 보조 행동도 최소 `48dp`를 보장한다. 장소명은 한 줄로
  과도하게 자르지 않고 카드 높이 안에서 두 줄까지 허용한다.
- 저장 상세는 저장·해제, 주소, 추천 이유, 운영시간·휴무, 태그와 지도를 한 흐름에서
  제공한다. 실제로 장소 검색을 여는 하단 행동은 `카카오맵에서 보기`로 정확히 표현한다.
- 같은 지역의 카탈로그를 성공적으로 불러온 뒤 다른 탭이나 상세에 다녀오면 기존 로드
  결과를 즉시 다시 표시한다. 지역 변경이나 명시적인 재시도 때만 첫 페이지 캐시를 무효화해
  재진입마다 스켈레톤과 순서 변화가 반복되지 않게 한다.

### 설정·계정·프로필

- 설정은 Scaffold 안전 영역을 한 번만 사용하고 콘텐츠를 최대 `640dp` 안에서 중앙
  정렬한다. 설정 행은 최소 `48dp` 이상과 버튼 역할을 가지며, 준비 중인 위치기반서비스
  이용약관에는 클릭 동작과 chevron을 노출하지 않는다.
- 로그인·계정 처리 중과 오류 상태는 live region으로 전달한다. 프로필 정보가 없어 실제
  진입할 수 없는 행은 눌리는 모양으로 남기지 않는다.
- 프로필 폼은 큰 화면 최대 폭, 키보드 inset, IME 완료 행동, 닉네임 글자수와 저장 중 상태를
  제공한다. 계정 삭제 재인증 버튼은 disabled 상태에서도 빨간 활성 글자로 보이지 않게 한다.
- 계정 삭제와 캐시·저장 확인창은 불투명한 흰 surface, 일관된 radius와 최대 폭, 최소
  `48dp` 버튼을 사용한다. 파괴적 확인은 주 행동으로, 취소는 보조 행동으로 구분한다.

### 최종 실기기 보정

- 중앙 지도 탭이 하단 영역 밖으로 늘어나 본문 터치를 덮던 회귀를 제거하고, 하단 탭은
  큰 글자에서도 내용에 맞춰 높이가 늘어나도록 최소 높이만 둔다.
- 접힌 LOCATION 패널은 큰 제목을 잘라 보여 주지 않고 `도착 시각 · 출발지 → 목적지`를
  한 줄 요약으로 표시한다.
- 선택 핀은 최소 줌 15와 라벨·지도 UI 여백을 사용해 선택 장소와 경로가 헤더·시트에
  가리지 않게 한다.
- 선택 결과 시트는 글자 배율에 따라 `420dp × fontScale`, 최대 `590dp`까지 늘어나며,
  그보다 큰 내용은 스크롤로 모두 도달할 수 있게 한다.

### 검증 상태

통합 자동 검증 132/132, lint 오류 0, 기본 글자 크기 실기기 시각 회귀 3/3을 통과했다.
글자 배율 1.3·2.0 핵심 경로와 위치 권한 거부 대체 흐름, 카카오맵 실제 3점 경로 전환도
통과했다. 최종 화면 21장과 서명된 release APK의 경로·크기·해시, 이번에 제외한 호환성
행렬은 `docs/08_QA_AND_KNOWN_ISSUES.md`에 기록했다.
