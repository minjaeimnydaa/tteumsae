# 공모전 사용자·알고리즘 검증 템플릿

> **상태: 레거시 검증 양식.** 현재 양식의 순수 여유시간·안전여유·`1/5` 문항은
> 신규 도착 마감 제품과 맞지 않는다. Gate 2 구현 후 5초 목적 이해, 도착 마감 입력,
> 한 곳 선택, 거짓 가능 판정과 외부 내비 실행 지표로 교체한다.

이 문서는 아직 수집하지 않은 성과를 채워 넣는 빈 양식이다. 빈칸을 0이나
추정값으로 대신하지 않는다. 원본 기록과 계산 근거가 없는 수치는 발표·영상·
제안서에 사용하지 않는다.

## 1. 검증 공통 원칙

- 참가자는 이름 대신 `U01` 같은 식별자를 사용한다.
- 정확한 현재 위치, 집 주소, 계정 화면과 API 키를 결과 자료에 남기지 않는다.
- 테스트 기기, 앱 버전, Git commit과 날짜를 고정해 기록한다.
- 실패와 중도 포기를 제외하지 않는다.
- 10~15명 사용자 테스트는 탐색적 검증이며 모집단 전체의 통계적 효과로
  일반화하지 않는다.
- 알고리즘 비교는 같은 출발지·목적지·관심사·시각·후보 데이터로 수행한다.
- 앱의 시간 입력은 기본 이동시간을 제외하고 경유에 쓸
  `순수 여유시간(extraTimeMinutes)` 15~1,440분이다.
- 안전여유는 순수 여유시간보다 작아야 하며, 모든 검증에서 다음 공식을 같은
  의미로 사용한다.

```text
우회 주행시간 + 기본 머무름 + 안전여유 ≤ 입력한 순수 여유시간
```

## 2. 10~15명 사용자 테스트

| 참가자 수 | 목표 10~15명 / 실제  |

| 동의 방식 | 익명 관찰·화면 녹화·인용 동의 여부 기록 |

표준 과업:

1. 홈 안내만 보고 이 앱이 무엇을 도와주는지 말한다.
2. 제시된 출발지와 강원도 목적지를 설정한다.
3. 제시된 순수 여유시간과 그보다 작은 안전여유를 입력하고 두 값의 의미를
   말한다.
4. 제시된 관심사를 고르고 결과로 이동한다.
5. 후보 한 곳을 경유지로 추가하고 총시간·`1/5`의 의미를 설명한다.
6. 장소 상세에서 운영정보가 확정인지 확인이 필요한지 판단한다.
7. 카카오맵에 경유지와 최종 목적지를 전달한다.

진행자는 막힌 즉시 답을 주지 않는다. 30초 이상 진행하지 못할 때만 사전에
정한 최소 힌트를 제공하고 힌트 횟수를 기록한다.

## 3. 20~30개 경로 알고리즘 검증

### 3.1 표본 설계

- 강원 동해안, 산악권, 도시권, 장거리 진입 경로가 한 유형에 치우치지 않게
  20~30개 출발지·목적지 쌍을 정한다.
- 개인정보가 아닌 역·터미널·시청·공영주차장 등 재현 가능한 지점을 사용한다.
- 요청 시각과 운영 DB 동기화 시각을 기록한다.
- 각 경로에서 동일 관심사로 현재 추천과 비교 기준을 실행한다.
- 비교 기준은 최소 `직선거리 가까운 순` 또는 `단순 반경 후보` 중 하나로
  정하되, 구현하지 않은 비교 결과를 만들어내지 않는다.
- 각 경로에 15~1,440분의 `extraTimeMinutes`와 그보다 작은 안전여유를
  사전에 정하고 현재 방식과 비교 기준에 동일하게 적용한다.

필요한 만큼 R20~R30까지 행을 복제한다. `우회 분`은 같은 시각·조건에서
`경유경로 주행시간 - 기본경로 주행시간`으로 계산한다. `시간 적합`은 다음
규칙으로 판정한다.

```text
필요한 추가시간 = 우회 주행시간 + 기본 머무름
시간 적합 = 필요한 추가시간 + 안전여유 ≤ 입력한 extraTimeMinutes
```

현재 앱의 기본 머무름은 카테고리별 휴리스틱이다. 사용자 실측 평균으로
표현하지 않는다.

## 4. 공모전 제출용 증거 묶음

- [ ] 익명 참가자별 원본 결과표
- [ ] 경로 R01~R20 또는 R30의 원본 요청 조건과 응답 기록
- [ ] 결과 계산식이 들어간 요약표
- [ ] 앱 버전·commit·APK SHA-256
- [ ] 테스트 기기와 네트워크 조건
- [ ] 성공 사례뿐 아니라 실패·중도 포기 목록
- [ ] 대표 화면 녹화와 캡처 파일명
- [ ] TourAPI 동기화 시각과 사용 필드 목록
- [ ] 발표 자료의 모든 숫자와 원본 행을 연결하는 근거 열

발표 문구는 증거 수준에 맞춘다.

| 증거 상태 | 사용할 표현 |
|---|---|
| 실제 측정 완료 | `테스트 참여자 n명 중 x명`, `검증 경로 n개에서 x건`처럼 표본과 함께 표현 |
| 소규모 탐색 결과 | `초기 사용자 테스트에서 관찰`로 한정 |
| 아직 미측정 | `목표`, `기대효과`, `향후 검증 항목`으로 분리 |
| API 또는 휴리스틱 추정 | `예상`, `기본값`, `확인 필요`를 함께 표시 |
