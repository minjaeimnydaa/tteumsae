# 최신 Android 메인 흐름 상용화 UX·UI 검토

검토일: 2026-09-11. 대상 소스: `9de381f`, Android `0.12.7` / versionCode 28.
출시 방향: 원스토어. 이 문서는 개선 제안이며 제품 변경을 실행한 기록은 아니다.

## 1. 검증 범위와 근거

사용자 승인 후 기존 앱을 삭제하고 최신 Debug APK를 설치했다. ADB package 조회에서
versionCode 28 / versionName 0.12.7을 확인했다. 기존 0.12.4에서 얻은 결과는 제외한다.
APK SHA-256: `26560C5382EE2D64002BAA096BC62D0ED2CC6C7B4DE0319D567DF19BDF8FBDB0`.

- Samsung SM-F776N, Android 17, 1080×2520, 원래 density 450 및 font_scale 0.9.
- 운영 백엔드로 안목해변 → 경포대, 기본 도착 마감 09:36, 카테고리 제한 없이 검색했다.
- 입력 → 강원 밖 검색 선택 차단 → 강원 목적지 → 추천 8곳 → 강릉 한우타운 선택 →
  상세 → 결과 복귀 → 카카오맵 3점 경로 전달을 실제 수행했다. 내비 주행은 시작하지 않았다.

  결과 장소명·주소·화면 UI는 한국어로 확인했다. 한글 IME 조합 테스트를 대체하지 않는다.
- 같은 폰의 density 변경으로 320dp 폭, font_scale 1.0 및 2.0 결과 화면을 확인했다.
  원래 폭 약 384dp에서 1.3 글자도 확인했다. 600dp는 홈만 확인했다.
- 320dp / 글자 1.0에서 결과 뒤로 → 입력 → 홈 → 장소 탐색 → 설정 → 로그인 시트 → 홈 통과.
- 설정은 density 450, font_scale 0.9로 복구했고 최신 앱을 홈에 남겼다.
- 여러 실제 기종, 3버튼 내비, 가로 화면·폴더 접힘 전환, TalkBack, 로그인 완료,

- 실제 폰 이동 없이 고정 출발·목적 좌표를 입력했다. 주차·대기·정시 도착의 현실 오차는 측정하지 않았다.

스크린샷은 `tmp/ux-audit-20260911/`에 있으며 Git에서 제외된다. 아래 경로는 이 PC의
실측 근거다. 다른 PC에는 별도 전송해야 하며 구버전 폴더와 혼동하지 않는다.

## 2. 전체 판단

핵심 흐름은 실제 작동한다. 입력을 한 화면에 모으고, 한 곳을 고른 뒤 체류 가능시간과
출발 시각을 보여주는 구조는 유지할 가치가 있다. 주요 CTA도 충분히 크다.
그러나 상용화 전에는 기능 수보다 사용자가 판단에 필요한 정보를 제때 보고 신뢰할 수 있는지가
더 중요하다. 특히 좁은 화면에서 상단 행동이 가려지고, 서비스 범위 설명이 화면 밖에 있으며,
장소 정보가 부족한 상세에서는 주차장 원문이 화면을 지배한다.

P1은 출시 전 우선 수정, P2는 초기 완성도 개선, P3는 사용자 검증 후 선택할 개선이다.

## 3. 출시 전 우선 수정

### P1-1. 강원 밖 장소를 눌러도 설명이 보이지 않는다 — 실기기 재현

`Seoul` 검색 결과에 `현재 지원 지역 아님` 배지는 보이고 선택도 차단된다.
하지만 탭 후 지원 범위 설명은 10개 결과 아래에 렌더링돼 첫 화면에는 나타나지 않는다.
하단 CTA 위에는 계속 `목적지를 선택해 주세요`가 보여 사용자가 다음 행동을 알기 어렵다.

- 근거: `latest2/screenshots/latest-03-unsupported.png`, `latest-04-unsupported-tapped.png`.
- 코드: `ui/route/LocationScreen.kt`의 결과 목록 뒤 `searchMessage` 렌더링.
- 개선: 목적지 입력 바로 아래에 `현재는 강원도 목적지를 지원해요`를 배치하고 비지원 탭 시
  같은 위치에서 피드백한다. 배지는 짧고 차분하게 유지한다. 목록 전체를 붉은 경고로 만들 필요는 없다.
- 완료 기준: 스크롤·키보드 유무와 관계없이 탭 직후 이유와 다음 행동을 확인할 수 있다.

### P1-2. 작은 화면·큰 글자에서 결과 시트가 상단 행동을 덮는다 — 실기기 재현

320dp 폭 / 글자 2.0에서 선택 결과의 시트가 제목을 덮고 뒤로·재조회 접근도 막는다.
장소명 옆 상세 버튼이 가로 공간을 차지해 `경유 +0분 · 최대 30분`이 여러 줄로 찢어진다.
출발 권장 시각과 알림은 첫 화면 아래로 밀린다. 아래로 스크롤할 수 있다는 사실만으로
상단 행동 접근성과 시간 정보의 가독성 문제가 해결되지는 않는다.

- 근거: `width320-font2.png`; 320dp/font1.0은 `small/screenshots/latest-320-result.png`.
- 코드: `ResultsScreen.kt`의 시트 peek 380/420~590dp, 목록 최대 590dp 및 지도 위 상단 바.
  `RouteResultComponents.kt`는 시간 지표만 세로 전환하고 카드의 제목·상세 가로 배치는 유지한다.
- 개선: 실제 가용 높이·상단 바·하단 CTA를 기준으로 시트 상한을 계산한다. 큰 글자에서는
  장소명, 추가 이동, 상세 행동을 세로로 분리한다. 상단 뒤로·재조회가 항상 접근 가능해야 한다.
- 완료 기준: 320dp/384dp, 글자 1.0/1.3/2.0에서 제목·뒤로·재조회·주 행동이 가려지지 않고
  장소명과 시간 값을 불필요하게 한 단어씩 줄바꿈하지 않는다.

### P1-3. 체류시간의 계산 기준과 영업 불확실성이 결과에서 약하다 — 실측 + 코드

08:37 계산 결과에 `최대 30분`이 노출됐다. 08:39에도 같은 값이 유지됐다.
코드는 현재시각으로 마감 만료는 확인하지만 maximumStayMinutes는 마지막 응답 값을 표시한다.
이 자체가 오류는 아니지만 사용자가 지금 출발해도 같은 시간을 쓸 수 있다고 읽기 쉽다.
또 첫 결과인 식당은 상세에 가서야 `운영 확인 필요`를 확인했다. 추천 목록에는 OPEN일 때만
운영 배지를 보여주므로 UNKNOWN은 눈에 띄지 않는다.

- 근거: `latest2/screenshots/latest-08-selected.png`, `continuation/screenshots/latest-10-detail-loaded.png`,
  `small/screenshots/latest-320-result.png`.
- 개선: `지금 출발하면 약 30분`, `경유지에서 09:17까지 출발 권장`처럼 기준을 명시한다.
  일정 시간이 지난 결과에는 `계산 후 N분 지남 · 다시 확인`을 노출한다. 임의로 시간을 차감해
  실시간 위치 추적처럼 보이게 하지 않는다. 자동 재조회는 기존 범위 밖이므로 수동 갱신을 우선한다.
  식당 등에서는 `영업시간 확인 필요`를 선택 전에 표시한다.
- 완료 기준: 사용자가 계산시각, 경유지 출발시각, 영업 확인 여부를 상세 진입 없이 구분한다.

### P1-4. 주차장 데이터가 실제 이용 가능성을 충분히 설명하지 못한다 — 실측

선택 식당의 상세에 주변 주차장 3곳이 노출되지만 그중 하나는 이름에 `거주자우선`이 포함되어 있다.
`무료`, 면수, 운영시간만 강조하면 방문객이 바로 사용할 수 있는 공간으로 오해할 수 있다.
`직선 약` 표시 자체는 적절하며 실제 도보시간으로 바꾸면 안 된다.

- 근거: `continuation/screenshots/latest-11-detail-bottom.png`.
- 개선: 거주자우선·이용자 제한은 명시적 원천 근거가 있으면 경고하고 일반 방문 가능 여부가
  불명확하면 확인 필요로 처리한다. 원천 이름의 단어만으로 이용 가능성을 확정하지 않는다.
  첫 화면에는 가까운 1곳 요약과 `주차장 더 보기`를 제공한다.
- 완료 기준: 제한형 주차장을 자유 이용 가능한 무료 주차장처럼 제시하지 않는다.

## 4. 화면별 UX와 기능 연결

| 화면 | 현재 장점 | 개선점과 권장 방향 |
|---|---|---|
| 홈 | 목적지 검색 CTA가 크고 로그인 없이 시작 가능 | `오늘 하루 보지 않기` 안내는 재방문 장벽. 최초 1회 또는 도움말로 이동. 홈 문구에 도착 시각 기반 가치와 강원 범위를 간단히 노출 |
| 입력 | 출발·목적·도착 시각이 한 화면, 56dp 이상 주 버튼 | 선택 장소 수정에 X가 필요하고 주소가 잘림. 선택 행 탭으로 수정, 주소 확인 수단 추가. `도착 마감`은 `몇 시까지 도착해야 하나요?`로 자연스럽게 설명 |
| 검색 | 최대 10개, 전국 출발지, 비지원 목적지 차단 | 10개 목록이 시간·필터를 아래로 밀어냄. 같은 화면 내 검색 모드에서 입력과 결과에 집중하고 선택 후 입력 요약으로 복귀. 새 필수 단계는 추가하지 않음 |
| 시간 | 추가 팝업 없이 시각 입력 가능 | 132dp 고정 휠의 면적이 크고 기본값 1시간 뒤가 실제 약속으로 오인될 수 있음. 선택 시각을 가장 선명하게 표시하고 직접 시각 수정 접근성도 검토 |
| 필터 | 선택하지 않아도 진행 가능 | 관광지·문화시설·레포츠 등 공급자 분류보다 식사·카페·산책·실내 같은 방문 의도가 이해하기 쉬움. 기존 매핑과 결과 수를 확인해 후속 변경 |
| 로딩 | 취소 가능, 불투명 진행 카드 | 단계 표시가 실제 서버 진행이 아니라 700ms 타이머 기반. 긴 대기 때는 단일 상태 + 지연 안내로 정직하게 표현. 결과 이후 지도 로딩도 별도로 발생 |
| 결과 | 추가 이동·체류·출발 권장과 한 곳 선택이 연결됨 | 상단·시트 헤더에 계산시각/개수가 반복됨. 상단은 목적지·도착 시각, 시트는 후보 비교에 집중. 선택 카드 내 반복 문구 축소 |
| 상세 | 결과 시간 요약을 유지하고 직접 카카오맵 실행 가능 | 첫 표본에 사진·소개·영업 정보가 부족한 반면 주차장 원문이 길다. 사진 없는 16:9 빈 영역 축소, 방문 이유/운영/요금/주차 우선. 추가 원천 정보는 접기 |
| 카카오맵 전환 | 3점 전달을 실제 확인 | 결과에서는 `이곳 들러 카카오맵 안내`, 상세에서는 `카카오맵에서 경유지로 안내`로 표현이 다름. 동일 행동 문구로 통일 |
| 장소 탐색 | 지역·필터·찜과 상세가 제공됨 | 메인 경로 검색과 검색의 의미가 다름. `탐색 위치 검색` 대신 `장소명·주소 검색`. `추천순`이 실제로는 DEFAULT 입력 순서이므로 근거 없는 추천 표현 정리 |
| 설정·로그인 | 게스트 가능을 명시하고 로그인 강제하지 않음 | 프로필 설정만으로는 로그인 이득이 약함. 현재 선택 기능 유지, 아직 없는 찜 동기화를 약속하지 않음 |

상세와 결과에 시간 정보가 반복되는 것은 필요한 맥락 유지다. 이를 없애기보다 같은 용어와
형식으로 통일한다. 반면 결과 헤더 두 곳의 개수/계산시각 반복은 줄여도 된다.

상세에서 바로 길 안내하면 선택과 외부 실행이 한 번에 일어난다. 결과에서만 알림을 켤 수 있어
상세로 먼저 들어간 사용자는 알림 옵션을 지나칠 수 있다. 상세의 시간 요약 가까이에 같은
선택형 알림을 제공하거나, 선택 상태를 명확히 보여주는 공통 행동 영역을 사용하면 좋다.
강제 알림 팝업을 새 단계로 추가할 필요는 없다.

결과의 뒤로는 `startNewRouteSearch()`를 호출해 후보·선택·알림을 초기화하고 입력은 유지한다.
단순 조건 확인을 위한 복귀까지 새 검색으로 처리하는 것은 과하다. `조건 편집`과 `여행 종료`를
구분하고 실제 변경 여부에 따라 재검색하도록 개선을 검토한다. 이번에는 알림을 켜지 않아
예약 삭제는 실기기 검증이 아닌 코드 판단이다.

## 5. 버튼·터치 영역·시스템 바

- 주 CTA는 대체로 최소 높이 56dp, 뒤로·지우기·상세 행동은 48dp 이상을 지정한다.
  UI 계층의 결과 뒤로·재조회 영역은 원래 density에서 135px로 약 48dp다.
  작은 아이콘 자체가 작은 터치 영역이라는 뜻은 아니다.
- 11~12sp 보조 글자, 비지원 배지, 두 열 정보는 큰 글자에서 배치가 중요하다. 48dp 기준은
  시각 영역뿐 아니라 실제 터치 영역으로 확인해야 한다. 지도 핀은 별도 native SDK 영역이므로
  이번 계층 측정으로 통과 처리하지 않는다.
- 기본 세로·제스처 설정에서는 입력/상세 주요 버튼과 상태 바가 직접 겹치는 문제는 관찰하지 않았다.
- `LocationScreen.kt`의 상단 확보는 `maxHeight - 82.dp`에 의존한다. 주석도 상태 영역을
  고정 여백으로 추정한다. 결과의 `전체 경로`도 상단 82dp 고정이다. 노치·상태 바·가로 화면에
  일반화하기 어렵다. 실제 systemBars/displayCutout insets와 상단 콘텐츠 측정값으로 처리해야 한다.
- 큰 글자 결과의 겹침은 실제 재현, 다른 제조사 노치 겹침은 아직 위험 추정이다.
- 600dp 홈은 늘어난 지도와 전폭 검색창으로 표시됐다. 단일 폰의 밀도 변경이므로 태블릿/
  폴더블 전환 통과로 표현하지 않는다. 넓고 짧은 화면은 지도+목록 좌우 배치를 후속 검토한다.

## 6. 권장 실행 순서와 완료 기준

1. 검색 비지원 안내를 입력 근처로 이동하고 10건 목록의 스크롤/키보드 흐름을 정리한다.
2. 결과 시트의 가용 높이 계산, 큰 글자 카드 레이아웃, 고정 상단 행동을 수정한다.
3. 결과에 영업 확인 필요와 계산 경과 안내를 표시하고 시간 문구를 통일한다.
4. 사진 없는 상세의 빈 영역을 줄이고 주차장 정보 요약·이용 제한을 정리한다.
5. 결과·상세의 선택/알림/길 안내, 뒤로·조건 편집 상태를 일관되게 만든다.
6. 홈 안내·필터·탐색 용어를 다듬은 뒤 첫 사용자 5~10명으로 이해도와 완료 시간을 측정한다.

후속 실기기 행렬은 일반폰/작은 폰/폴더블, 글자 1.0/1.3/2.0, 제스처/3버튼, 키보드
열림·닫힘, 한글 입력, 네트워크 오류·빈 결과·마감 만료를 포함한다. 알림 실제 수신과
Release 서명 지도·로그인은 원스토어 제출용 빌드에서 별도로 확인한다.

새 기능의 수를 늘리기보다 처음 사용자가 `어디로 언제까지 → 여기 들르면 얼마나 → 언제 출발`
세 질문에 빠르게 답을 얻는 상태를 우선 목표로 삼는다. 실제 시간 정확도는 UI 검토와 별개로
정차·주차·현장 이동·대기시간을 포함한 실경로 감사가 필요하다.

## 7. 2026-09-11 후속 구현 기록

사용자 승인으로 우선순위 1~4의 코드 수정과 길 안내·탐색 용어 통일을 적용했다.
상단 조작을 시트 외부로 이동하고, 검색 안내를 입력 위계에 맞춰 이동하면서 누른
비지원 결과에도 이유를 표시한다. 주차장 UI는 별도 파일로 분리해 1곳 우선 표시한다.

이번 변경을 전체 감사 완료로 보지 않는다. 조건 편집 상태 보존, 상세 알림, 홈·필터,
실제 다기종 검증은 남아 있다. 최신 실행 상태는 09 계획과 08 QA를 따른다.

후속 실기기에서 비지원 안내, 추천 8곳·선택·상세 왕복, 주차장 펼침을 확인했다.
320dp/384dp × 글자 1.0·1.3·2.0의 상단/주 CTA 접근을 확인하는 과정에서 상단 문구 높이와
지도 위 전체 경로 버튼 겹침을 추가 발견했다. 큰 글자 상단을 축약하고 전체 경로를 선택 카드로
이동했으며, 최종 APK 320dp/글자 2.0에서 지도 확대·목록 복귀를 확인했다.
글자 2.0에서 시간 상세·알림은 스크롤이 필요하다. 이번 결과는 모든 항목의 첫 화면 노출이나
다기종 상용 QA 완료를 뜻하지 않는다. 테스트 후 폰의 원래 표시 설정을 복구했다.
