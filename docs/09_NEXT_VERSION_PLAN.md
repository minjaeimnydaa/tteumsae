# 다음 버전 개선 계획

이 문서는 현재 구현에서 무엇을 유지하고, 수정하고, 추가하고, 제거할지 결정하기 위한 작업 목록입니다. 우선순위는 `P0 인수 기준선`, `P1 다음 테스터 버전`, `P2 Play Store 제출 전`으로 나눕니다.

## 1. 유지할 것

| 대상 | 유지 이유 | 주의점 |
|---|---|---|
| Android 네이티브·Jetpack Compose | 현재 제품과 지도 SDK에 적합 | 대형 화면 파일은 분리 필요 |
| Vercel Functions | 현재 규모에서 운영 단순성 충분 | Rate Limit·관측성 보강 |
| Supabase Postgres | 장소 동기화와 페이지 조회에 적합 | 마이그레이션 절차 문서화 |
| TourAPI 사전 동기화 | 앱의 N+1 호출을 피함 | 상세 동기화 주기 개선 |
| 카카오 Local·Mobility | 국내 장소 검색·차량 경로에 적합 | 호출량·오류 fallback 관리 |
| Kakao Map Android SDK | 실제 지도 표시가 안정적으로 동작 | 패키지·키 해시 제한 유지 |
| 최대 경유지 5개 | 카카오맵 전달 제약과 일치 | UI에 `n/5` 명시 |
| 브랜드 색상 `#E60F33` | 디자인 가이드 공식 키 컬러 | 파생색을 토큰화 |
| 서버 전용 외부 API 키 | 클라이언트 비밀 노출 방지 | 환경변수만 사용 |

## 2. P0 — 인수 기준선 완성

### 2.1 최신 소스 기준 커밋

완료 조건:

- [ ] Android, 백엔드, 다운로드 페이지와 문서가 같은 저장소에 있다.
- [ ] `.env.local`, `local.properties`, `.vercel`, APK, 키스토어가 추적되지 않는다.
- [ ] 백엔드의 미커밋 기능이 기준 커밋에 포함된다.
- [ ] 새 빈 폴더에 clone한 저장소에서 빌드할 수 있다.

### 2.2 Android 단위 테스트 실행 복구

완료 조건:

- [ ] `testDebugUnitTest`가 테스트 클래스를 로딩한다.
- [ ] 기존 테스트가 모두 통과하거나 실제 결함으로 분류된다.
- [ ] 영문 경로 Windows 환경에서 결과를 기록한다.

### 2.3 최신 소스 APK 재빌드

완료 조건:

- [ ] 버전 번호를 증가한다.
- [ ] 카테고리 핀과 선택 순서 배지가 APK에 포함된다.
- [ ] 실제 기기 스모크 테스트를 통과한다.
- [ ] APK는 Git이 아니라 다운로드 배포 서비스에만 둔다.

### 2.4 계정 접근 인수

완료 조건:

- [ ] GitHub, Vercel, Supabase, Kakao, 공공데이터포털 접근 소유자가 지정된다.
- [ ] 실제 키 값은 Git과 문서 밖의 보안 채널로 관리한다.
- [ ] 계정 복구 코드가 로컬 작업 폴더에서 제거되고 안전하게 보관된다.

## 3. P1 — 다음 테스터 버전

### 3.1 시간 입력 의미 확정

결정할 것:

- 전체 남은 시간을 입력받을지
- 기본 이동시간을 먼저 계산하고 순수 여유시간만 입력받을지

권장 순서:

1. 기본 출발→목적지 경로 API 계약을 추가한다.
2. 기본 이동시간을 화면에 보여준다.
3. 사용자가 순수 여유시간을 입력한다.
4. 백엔드 요청 의미를 새 필드로 명확히 한다.

완료 조건:

- [ ] 화면 문구, Android 모델, API 검증, 추천 공식과 테스트가 같은 의미를 사용한다.
- [ ] 기존 클라이언트 호환 여부가 결정된다.

### 3.2 결과 화면 최신 디자인

추가·수정:

- 상단 `총 소요시간` 카드
- 우측 `경유지 n/5` 배지
- 거리와 통행료 표시 여부
- 지도 위 가로 카드 캐러셀
- 대표 이미지와 `장소 1/20`
- CTA의 `경유지 추가`·`경유지에서 빼기`
- 지도 선택 핀의 순서 동기화

완료 조건:

- [ ] `장소 1/20`, `경유지 2/5`, 지도 순번의 의미가 겹치지 않는다.
- [ ] 카드 스와이프 시 해당 핀과 카메라가 동기화된다.
- [ ] 지도 핀 선택 시 해당 카드가 보인다.
- [ ] 작은 화면에서도 CTA가 시트 안에서 완전히 보인다.

거리·통행료가 현재 API 응답에 충분하지 않으므로 UI부터 하드코딩하지 않습니다. 먼저 API 필드를 확정합니다.

### 3.3 복수 경유지 실제 재계산

현재 앱 합산 추정을 백엔드 통합 경로 계산으로 교체합니다.

완료 조건:

- [ ] 선택한 경유지 목록을 서버가 받는다.
- [ ] 서버가 출발지·경유지·목적지 전체 경로를 계산한다.
- [ ] 실제 순서, 총시간, 거리와 가능하면 통행료를 반환한다.
- [ ] 후보 추가·삭제 시 디바운스 또는 명시적 재계산을 사용한다.
- [ ] API 비용과 Rate Limit을 방어한다.
- [ ] 실패 시 기존 예상값과 명확히 구분된 fallback을 제공한다.

### 3.4 후보 영역 정확도

선택지:

1. 실제 경로에서 일정 우회거리 이내의 corridor
2. 후보별 허용 우회시간으로만 필터하고 시각 영역은 제거
3. 서버가 계산한 경로 기반 polygon

완료 조건:

- [ ] 붉은 영역의 의미를 사용자가 이해할 수 있다.
- [ ] 표시 영역과 실제 후보 필터가 같은 기준을 사용한다.
- [ ] `100% 보장` 표현을 사용하지 않는다.

### 3.5 카페·의도 추천 품질

- TourAPI 세부 카테고리로 카페를 분리합니다.
- `실내 활동`, `지금은 음식 제외` 매핑을 실제 데이터로 검증합니다.
- 결과가 적을 때 어떤 조건을 완화했는지 보여줍니다.

완료 조건:

- [ ] 카페 선택 시 카페 결과가 실제로 존재한다.
- [ ] 음식 제외에 음식점과 카페가 포함되지 않는다.
- [ ] 테스트 데이터가 아닌 운영 DB로 결과 분포를 기록한다.

### 3.6 장소 둘러보기와 저장소 목적 확정

현재 탭은 전체 TourAPI 카탈로그와 저장 기능을 함께 제공합니다.

결정 선택지:

- `장소 둘러보기`로 이름을 바꾸고 전체 카탈로그 중심으로 유지
- `틈새 저장소`로 유지하고 저장한 장소만 우선 제공
- 화면 안에서 `전체`와 `저장`을 명확히 분리

완료 조건:

- [ ] 탭 이름과 실제 첫 화면 내용이 일치한다.
- [ ] 서버 전체 검색인지 내려받은 목록 검색인지 사용자에게 혼동을 주지 않는다.
- [ ] 저장한 장소가 페이지 로딩 여부와 무관하게 항상 보인다.

### 3.7 운영·오류 대응

- 공개 API Rate Limit 또는 앱 요청 정책
- 구조화 로그와 오류 추적
- Cron 실패 알림
- 상세 동기화 배치 크기 측정·조정
- 제거된 TourAPI 장소 비활성화

완료 조건:

- [ ] 추천 API의 외부 API 최대 호출량이 제한된다.
- [ ] Cron 실패를 담당자가 알 수 있다.
- [ ] 장소 상세 데이터의 전체 갱신 주기를 계산할 수 있다.

## 4. P2 — Play Store 제출 전

### 4.1 Android 구조 정리

최소 분리 목표:

```text
ui/home/
ui/search/
ui/results/
ui/saved/
ui/settings/
data/api/
data/local/
domain/
```

- 화면별 Composable을 분리합니다.
- 탐색 상태를 ViewModel로 이동합니다.
- 프로세스 복원을 `SavedStateHandle` 또는 저장 가능한 상태로 정의합니다.
- API 모델과 화면 모델의 경계를 분명히 합니다.

완료 조건:

- [ ] `TteumsaeApp.kt`가 화면 조립과 탐색 역할만 가진다.
- [ ] 회전·프로세스 재생성 후 결과 화면이 잘못 복원되지 않는다.
- [ ] 구조 변경 전후 핵심 흐름 회귀 테스트가 있다.

전면 아키텍처 재작성은 하지 않습니다. 다음 기능을 수정할 때 해당 화면부터 점진적으로 분리합니다.

### 4.2 정책과 개인정보

- 개인정보처리방침 공개 URL
- 위치기반서비스 관련 약관 또는 고지
- 위치 사용 목적과 보관 여부
- 저장 장소 데이터와 Android 백업 정책 검토
- 문의 메일의 회사 계정 전환

완료 조건:

- [ ] 설정 화면과 Play Console에 같은 정책 URL을 사용한다.
- [ ] 실제 데이터 수집·전송과 정책 문구가 일치한다.

### 4.3 릴리스 체인

- 앱 아이콘과 adaptive icon
- 스플래시
- 릴리스 signingConfig
- AAB
- Play App Signing
- 버전 증가 규칙
- 내부 테스트 트랙
- 스토어 스크린샷·설명·데이터 보안 설문

### 4.4 접근성과 품질

- 48dp 이상 터치 영역
- 아이콘 contentDescription
- 글자 확대
- 색 대비
- TalkBack 탐색 순서
- 작은 화면·긴 한글 텍스트
- 주요 Android 버전 실기기 테스트

## 5. 제거 후보

제거 전 `rg`로 사용처가 없는지 다시 확인합니다.

| 대상 | 현재 판단 | 제거 조건 |
|---|---|---|
| `android/.../data/SamplePlaces.kt` | 운영 미사용 | 오프라인 데모 계획 없음 |
| `DataContracts.kt`의 샘플 저장소·경로 제공자 | 운영 미사용 | 새 구조에서 채택하지 않음 |
| `android/.../domain/TimeSafeEngine.kt` | 운영 미사용 | 백엔드 알고리즘만 유지 |
| 관련 `TimeSafeEngineTest.kt` | 제거 코드 테스트 | 엔진 제거와 함께 |
| `backend/vercel.json`의 v0.4.0 APK rewrite | 오래된 별도 배포 경로 | `tteumsae-apk`만 사용 |
| 백엔드 과거 APK·sha256 | 운영에 불필요 | 외부 릴리스 보관 확인 |
| TourAPI cleartext network 예외 | Android 직접 호출 없음 | 실제 런타임 확인 후 |

## 6. 결정이 필요한 항목
