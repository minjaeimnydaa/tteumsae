# 공모전 90초 데모와 실기기 제출 게이트

기준 흐름: `HOME → LOCATION → LOADING → RESULTS → DETAIL`

이 문서는 Gate 2 도착 마감·한 곳 선택 흐름의 시연 기준이다. 전체 회귀 항목과
알려진 문제는 [QA와 알려진 문제](08_QA_AND_KNOWN_ISSUES.md)를 따른다.

## 1. 시연에서 지킬 제품 경계

- 사용자는 출발지, 목적지와 도착해야 할 시각을 입력한다.
- 안전여유 10분과 최소 체류 15분은 서비스가 관리하며 사용자에게 입력받지 않는다.
- 지도 핀은 추가 이동시간 `+N분`을 보여준다.
- 사용자는 경유지 없음 또는 한 곳을 선택한다.
- 선택한 장소에는 이동 기준 최대 체류시간과 늦어도 출발할 시각을 보여준다.
- 실제 최종 경로와 시간은 카카오맵에서 다시 계산한다.
- 결과는 현재 교통 기준 예상이며 도착 보장이나 실시간 추적이 아니다.

- 카카오맵 설치/미설치 fallback을 모두 확인한다.
- 알림 권한 허용과 거부 시나리오를 확인한다.
- 라이브와 같은 커밋·APK의 90초 백업 영상을 준비한다.
- API 키, 개인 주소와 계정 알림이 화면에 노출되지 않게 한다.

## 3. 90초 골든 데모

| 시간 | 화면 동작 | 발표 문장 |
|---:|---|---|
| 0~8초 | 홈 지도와 목적지 검색 | “틈새는 목적지에 늦지 않도록, 이동 중 들를 한 곳을 찾는 앱입니다.” |
| 8~25초 | 출발지·목적지·도착 마감을 한 화면에서 입력 | “어디서 출발해 어디에 몇 시까지 도착할지만 정합니다.” |
| 25~35초 | 필요하면 관심 필터 선택 후 틈새 찾기 | “관심사는 선택이고, 별도 복잡한 설정 없이 바로 찾을 수 있습니다.” |
| 35~52초 | 결과 지도와 `+N분` 핀 표시 | “핀은 장소별 추가 이동시간만 보여줘 빠르게 비교할 수 있습니다.” |
| 52~68초 | 후보 한 곳 선택, 최대 체류·출발 마감 표시 | “선택하면 이곳에 최대 얼마나 머물고 언제 출발해야 하는지 계산합니다.” |
| 68~78초 | 선택형 출발 알림 켜기 | “원하면 출발 5분 전에 기기 알림을 받을 수 있습니다.” |
| 78~90초 | 카카오맵 안내 실행 | “실제 길 안내는 익숙한 카카오맵에서 이어갑니다.” |

발표 중 `100% 안전`, `절대 늦지 않음`, `실시간 추적`, `AI 최적 경로`는
사용하지 않는다. 장소·시간 수치는 리허설에서 실제로 나온 값만 읽는다.

## 4. 핵심 실기기 QA 기록

| ID | 확인 항목 | 기대 결과 | 결과·증거 |
|---|---|---|---|
| LOC-01 | 위치 권한 허용 | 현위치와 주소 표시, 진행 가능 |  |
| LOC-02 | 위치 권한 거부 | 직접 출발지 검색 가능 |  |
| TIME-01 | 인라인 시·분 휠 | 1시간 뒤 기본값과 탭·스와이프가 즉시 반영 | 2026-08-28 SM-F776N 통과 |
| TIME-02 | 15분·24시간·자정 넘김 | 경계와 다음 날 해석이 정확함 |  |
| ROUTE-00 | 경유지 미선택 CTA | 목적지 직행 카카오맵 |  |
| ROUTE-01 | 한 곳 선택·교체·해제 | 동시에 한 곳만 선택 |  |
| ROUTE-02 | 최대 체류·출발 마감 | 서버 응답과 화면 일치 |  |
| REFRESH-01 | 현재 교통 재확인 | 성공 갱신, 실패 시 기존 결과 유지 |  |
| ALARM-01 | 알림 권한 허용 | 출발 5분 전 알림 |  |
| ALARM-02 | 알림 권한 거부 | 길 안내는 그대로 동작 |  |
| BACK-01 | 로딩 중 뒤로 | LOCATION 복귀, 늦은 결과 재등장 없음 |  |
| BACK-02 | RESULTS→DETAIL→RESULTS | 선택 상태 유지 |  |
| UI-01 | 320dp·큰 글자 | 핵심 문구와 CTA가 겹치지 않음 |  |
| ERR-01 | 네트워크 끊김/복구 | 실패 설명과 재시도, 비정상 종료 없음 |  |

각 결과에는 날짜, 기기/OS, commit, APK SHA-256, 환경, 스크린샷 또는 영상을 남긴다.
