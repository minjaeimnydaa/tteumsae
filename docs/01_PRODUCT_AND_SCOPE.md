# 제품 범위와 방향

기준일: `2026-08-28`

이 문서는 틈새가 앞으로 만들 제품의 기준이다. 현재 코드의 실제 구현 여부는
[기능 구현 현황표](03_FEATURE_MATRIX.md)와 [화면 흐름](04_SCREEN_FLOWS.md)에서 확인한다.

## 1. 한 문장 정의

> 목적지는 그대로 두고, 반드시 도착할 시각을 지키면서 가는 길에 의미 있게 들를 한 곳과 머물 수 있는 시간을 알려주는 서비스

틈새는 일반 관광지 카탈로그나 여러 날 여행 플래너가 아니다. 핵심 질문은
`어디가 좋은가`보다 `지금 이곳을 들러도 되는가`다.

## 2. 핵심 사용자와 사용 순간

초기 사용자는 지금 자동차로 출발하려는 운전자 또는 동승자다.

- 호텔 체크인, 식당 예약, 공연·축제, 약속처럼 도착 마감이 있다.
- 45~180분 정도의 애매한 여유가 있지만 들렀다가 늦을까 불안하다.
- 장소 검색, 우회시간, 체류시간과 출발시각을 직접 계산하고 싶지 않다.
- 강원도 이동을 첫 검증 범위로 사용한다.

앱 조작은 출발 전 정차 상태나 동승 중을 전제로 한다. 운전자에게 주행 중 조작을
유도하는 문구를 사용하지 않는다.

## 3. 핵심 제품 약속

사용자가 제공하는 필수 정보는 출발지, 목적지와 반드시 도착할 절대 시각이다.
서비스는 다음을 제공한다.

- 직행 대비 추가 이동시간
- 최소 15분 이상 머물 수 있는 후보
- 장소 선택 후 이동 기준 최대 체류시간
- 가장 늦게 출발해야 하는 권장시각
- 후보가 안전하지 않으면 바로 출발하라는 빈 결과

대표 결과는 다음처럼 한눈에 이해되어야 한다.

```text
18:00까지 강릉 도착

카페 +6분
산책로 +11분

[카페 선택]
여기서 최대 약 35분 머물 수 있어요
늦어도 17:12 출발을 권장해요
```

## 4. 제품 원칙

1. 목적지와 도착 마감은 한 화면에서 입력한다. 시간 전용 단계를 만들지 않는다.
2. 사용자는 체류시간과 안전여유를 입력하지 않는다.
3. 내부 안전여유는 10분, 최소 의미 체류시간은 15분이다.
4. 관심 조건은 선택사항이다. 별도 필수 CONDITIONS 화면을 두지 않는다.
5. 첫 출시의 완료 경로는 경유지 한 곳이다.
6. 두 번째 장소는 한 곳 흐름의 실제 성과가 확인된 뒤 약한 선택지로 실험한다.
7. 핀은 `+8분`처럼 추가 이동시간을 보여주고 최대 체류시간은 선택 후 보여준다.
8. 실제 주행은 외부 카카오맵이 담당한다.
9. 틈새는 지속 위치 추적, 실시간 내비 또는 정시 도착을 보장한다고 표현하지 않는다.
10. 위치 추적 없는 고정 출발 알림을 우선하고 지오펜스는 후속 선택 기능으로 둔다.

## 5. 시간 모델 용어

### 도착 마감

Android는 상대 분 값이 아니라 `arrivalDeadlineEpochMillis` 절대시각을 서버에 보낸다.
서버는 수신 시각을 기준으로 남은 시간을 계산한다. 네트워크 지연이 도착 마감을 뒤로
미루지 않도록 상대 `deadlineMinutes`를 신규 계약의 기준으로 사용하지 않는다.

### 최대 체류시간

```text
maximumStayMinutes =
  floorTo5Minutes(
    도착 마감 - 서버 현재시각 - 전체 경유 이동시간 - 내부 안전여유
  )
```

경로 이동시간은 Kakao 응답 초를 분으로 올림하고, 체류 가능시간은 5분 단위로 내린다.
`maximumStayMinutes >= 15`인 후보만 제공한다.

### 출발 권장시각

```text
latestDepartureAt =
  도착 마감 - 경유지→목적지 이동시간 - 내부 안전여유
```

주차, 장소까지의 도보, 대기열과 입장 마감을 충분히 알지 못하는 동안 사용자 문구는
`여기서 최대 약 N분 머물 수 있어요`, `현재 교통 기준 예상`을 사용한다.

## 6. 관심 조건

관심 조건은 추천을 시작하기 위한 필수 단계가 아니라 결과를 좁히는 선택 필터다.

| 선택 | 기본 매핑 |
|---|---|
| 아무거나 | 카테고리 제한 없음 |
| 식사 | 음식점 |
| 카페 | 카페 |
| 산책·관광 | 관광지·레포츠 |
| 실내 | 문화시설·쇼핑 |
| 음식 제외 | 음식점·카페 제외 |

초기 화면은 `아무거나`로 바로 검색할 수 있어야 한다. 필터를 바꾸면 같은 도착 마감으로
후보를 다시 계산한다.

## 7. 장소 데이터와 추천 신뢰

TourAPI는 초기 카탈로그 공급원이지 제품의 해자가 아니다. 운영 DB의 2026-08-28
기준 고유 장소 1,719곳 중 대표 이미지 보유는 1,252곳(72.8%)이지만 운영시간 보유는
16곳(0.9%)이다.

초기 알파에서는 전체 장소 수보다 다음을 우선한다.

- 100~300개 핵심 장소의 운영시간·주차·입장 마감 검수
- 해석이 불확실한 운영시간은 `UNKNOWN`
- 불완전하거나 지난 축제 제외
- 운영시간이 없으면 `영업시간 확인 필요` 표시
- 후보 품질과 실제 방문 가능성을 우선한 내부 점수

장기 방어력은 장소 목록이 아니라 예상 대비 실제 우회, 주차·도보·대기, 추천 수락,
실제 시간 충분 여부와 정시 도착 피드백에서 만든다.

## 8. 현재 구현 상태

Gate 2 Android와 백엔드는 이 문서의 핵심 흐름을 코드로 연결했다.

- LOCATION에서 출발지·목적지·절대 도착 마감을 한 번에 입력
- 관심 조건은 선택 필터이며 별도 필수 화면 없음
- 서버 고정 안전여유 10분, 최소 체류 15분
- 핀은 추가 이동시간 `+N분` 표시
- 경유지 없음 또는 한 곳 선택
- 선택 후 최대 체류시간과 늦어도 출발할 시각 표시
- 선택형 로컬 출발 알림과 카카오맵 안내

자동 테스트와 빌드는 코드 계약을 검증할 뿐이며 실제 이동 정확도와 알림·지도·OAuth는
실기기 QA 전까지 제품 검증 완료로 간주하지 않는다.

## 9. 보장하지 않는 것

- 목적지 정시 도착 100% 보장
- 외부 내비와 동일한 실시간 턴바이턴 안내
- 이동 중 상시 위치 추적
- 영업시간이 없는 장소의 실제 영업 여부
- 주차·도보·대기시간을 알 수 없는 장소의 정밀 체류시간
- 현재 기기 로컬 저장 장소의 계정 간 동기화
- 세 곳 이상 일정 계획

`도착 보장`, `실시간 경로 추적`, `최적` 대신 `현재 교통 기준 예상`,
`늦을 위험을 줄이는 추천`, `이동 기준 최대`를 사용한다.

## 10. 초기 성공 기준

다음 값은 시장 성과가 아니라 알파 검증 통과 기준이다.

- 첫 화면 5초 내 목적 이해율 80% 이상
- 도움 없이 입력에서 결과까지 도달 70% 이상
- 초기 30개 실제 경로에서 잘못된 `들러도 됨` 판정 0건
- 무결과율 15% 미만
- 결과 사용자의 장소 선택률 30% 이상
- 장소 선택자 중 외부 내비 실행률 60% 이상

DAU보다 `추천 가능한 여행 → 결과 → 장소 선택 → 내비 실행 → 시간 충분 여부` 전환을
우선 측정한다. 측정 전에는 알고리즘 정확도나 사용자 성과를 실제 결과처럼 발표하지 않는다.

## 11. 단계별 범위

### 알파 핵심

- 목적지·도착 마감 한 화면 입력
- 선택형 관심 필터
- 한 곳 우선 추천
- 추가 이동시간, 최대 체류시간, 출발 권장시각
- 고정 로컬 출발 알림
- 외부 카카오맵 안내

### 검증 후 후보

- 정확 경로가 가능한 경우 두 번째 장소 제안
- 지오펜스 도착 감지
- 저장 장소 계정 동기화
- 전국 확대와 웹·딥링크 진입
- 사업자 운영·예약·대기 정보

### 비목표

- 여러 날 일정 자동 생성
- 범용 주변 맛집·관광지 피드 경쟁
- 대중교통 복합 경로
- 앱 내부 내비게이션
- 사용자가 직접 체류시간을 배분하는 화면
