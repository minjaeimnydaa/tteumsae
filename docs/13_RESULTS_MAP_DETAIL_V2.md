# 지도 후보 · 결과 목록 · 장소 상세 V2

구현일: `2026-09-05`

상태: Android 화면·실데이터 연결·자동 화면 회귀 구현 완료. TourAPI 소개·복수 사진을
지속 보강하는 서버 배치도 운영 배포를 마쳤으며, 일일 자동 배치가 기존 장소를 점진적으로
보강한다. 배포 직후 수동 5건 보강은 로컬 Cron 자격 증명이 운영값과 달라 실행하지 않았고,
운영 자격 증명을 별도로 노출하지 않은 채 예약 배치에 맡긴다.

## 1. 목표

경로 검색 이후의 흐름을 `지도에서 후보의 성격 파악 → 후보군 탐색 → 목록에서 비교 → 상세에서 방문 판단 → 길 안내`로 정리한다. 기존 디자인의 흰색·붉은색 중심 분위기는 유지하면서, 장식보다 판단에 필요한 정보와 조작 결과를 먼저 보이게 한다.

## 2. 발견된 문제

- 후보 핀은 `+N분`만 보여 장소 종류를 구분하기 어렵다.
- 후보·묶음 마커 비트맵 아래에 46dp의 투명 영역이 있어 실제 좌표와 핀이 떨어져 보인다.
- 묶음 클릭이 항상 현재 줌에서 2단계만 확대되어 `5곳 → 1곳 + 4곳 → 1곳 + 3곳`처럼 형식적으로 해체된다.
- 결과 목록이 큰 카드와 큰 여백의 반복이라 한 화면에서 비교할 수 있는 정보량이 적다.
- 선택된 카드가 두꺼운 붉은 테두리와 긴 문장으로 커져 핵심 수치의 위계가 흐리다.
- 상세 화면은 서버가 주는 실제 필드를 앱에서 버리고, 일반 문구를 추천 이유로 대체해 방문 정보가 빈약해 보인다.

## 3. 지도 후보 핀

### 단일 후보

- 기본 핀은 46×52dp를 기준으로 하고, 끝점이 좌표에 0~2dp 이내로 닿게 한다.
- `+N분` 텍스트 대신 카테고리 그림문자를 사용한다.
  - 관광지: 산/랜드마크
  - 음식점: 포크·스푼
  - 카페: 컵
  - 문화시설: 건물
  - 축제·행사: 별/불꽃
  - 쇼핑: 쇼핑백
  - 레포츠: 활동
- 색만으로 구분하지 않고 그림 형태를 함께 사용한다.
- 선택된 후보는 붉은색, 크기 증가, 얕은 후광으로 상태를 표시한다.
- 추가 이동시간은 지도에서 제거하고 목록과 선택 후 상세 영역에서 제공한다.

### 후보 묶음

- 묶음은 장소 수뿐 아니라 대표 카테고리 그림과 구성 수를 함께 보여준다.
- 한 번 누르면 현재 묶음이 의미 있게 풀리는 최초 줌을 계산해 이동한다.
- N이 4 이상일 때 `N-1 + 1`만 되는 줌은 건너뛴다.
- 다음 조건 중 하나를 처음 만족하는 줌을 선택한다.
  - 화면에 세 그룹 이상으로 나뉨
  - 가장 큰 하위 묶음이 기존의 약 2/3 이하가 됨
  - 전부 단일 후보로 분리됨
- 동시에 하단 목록을 `이 주변 N곳`으로 좁혀 모든 구성원을 바로 비교·선택할 수 있게 한다.
- 모든 좌표가 안전 영역 안에 들어오도록 맞춘 뒤, 누른 묶음에는 더 작은 화면거리
  임계값을 적용해 `N-1 + 1`이 아닌 복수 하위 묶음으로 즉시 드러낸다.
- 묶음 범위를 벗어난 지도 조작이나 `전체 추천 보기`로 전체 목록에 복귀한다.
- 줌 인/아웃 경계에는 기존 히스테리시스를 유지해 마커가 떨리지 않게 한다.

## 4. 결과 하단 목록

### 시트 헤더

- 제목: `경로 주변 추천 N곳`
- 보조 문구: `HH:mm 현재 교통 반영 · 한 곳 선택`
- 묶음 범위일 때: `이 주변 N곳` + `전체 추천 보기`
- 미선택 상태에서 2~2.5개 항목이 보여 스크롤 가능성을 자연스럽게 알린다.

### 목록 행

- 개별 큰 카드 대신 하나의 흰 컨테이너 안에서 1dp 연한 구분선으로 나눈다.
- 기본 행 높이는 약 104dp, 좌우 16dp, 상하 14dp를 기준으로 한다.
- 왼쪽 40dp 카테고리 아이콘, 중앙 정보, 오른쪽 선택 상태 순서로 배치한다.
- 텍스트 위계:
  1. 장소명
  2. `경유 +N분 · 최대 체류 X`
  3. 카테고리와 확인된 운영상태 태그. 운영상태 미확인은 경고 태그를 반복하지 않는다.
- 행 전체를 눌러 선택하며, `장소 정보 보기 ›`는 별도 명시적 행동으로 둔다.
- 선택 상태는 연한 배경, 왼쪽 3dp 강조선, 체크 아이콘으로 표현한다.

### 선택 확장 영역

- 제목: `이 경유지를 선택하면`
- 핵심 수치를 두 칸으로 분리한다.
  - `머물 수 있는 시간`
  - `출발 권장`
- `장소까지 X분 · 경유 +N분`은 보조 행으로 둔다.
- 알림은 벨 아이콘과 실제 알림 예정 시각을 보여주고, 긴 일반 설명은 제거한다.

## 5. 장소 상세

정보가 없는 섹션을 큰 빈 카드로 만들지 않는다. `정보 미제공`을 `불가`나 `휴무`로 단정하지 않는다.

노출 순서:

1. 사진 또는 작은 카테고리 대체 영역
2. 카테고리·운영상태, 장소명, 주소
3. 전화/홈페이지 등 즉시 행동
4. `이번 경로에서`
   - 추가 이동시간
   - 머물 수 있는 시간
   - 출발 권장시각
   - 장소까지 이동시간
5. `방문 전 확인`
   - 운영시간, 휴무, 입장/이용료, 예약, 주차, 문의, 행사 기간
6. `추가 안내` (`detailInfo2` 반복 상세가 있을 때만)
7. 장소 유형별 정보
8. `장소 소개` (`overview`가 있을 때만)
9. 데이터 출처와 검토/갱신일

기존 `추천 이유` 일반 문구는 제거한다. 추천 이유는 관광지 설명이 아니라 실제 경로 계산값으로 구성한 `이번 경로에서` 영역이 담당한다.

## 6. 데이터 적용 범위

### P0 — 이번 적용

- 기존 TourAPI `KorService2`와 현재 서버의 정규화 필드를 활용한다.
- 앱에서 현재 누락 중인 다음 필드를 보존·표시한다.
  - 전화, 홈페이지, 소개
  - 복수 사진 URL
  - 운영시간, 휴무, 마지막 입장
  - 주차 정보
  - 행사 시작/종료일
  - 데이터 출처, 운영정보 상태, 검토일
- 상세 진입 시 장소 단건을 다시 읽되, 실패하면 경로 결과에 포함된 스냅샷을 그대로 사용한다.
- 빈 값은 숨기고 임의 문구로 채우지 않는다.

### P1 — 후속 확장

- [x] TourAPI `detailInfo2`: 반복 안내를 상세 화면의 `추가 안내`로 제공
- [x] `detailImage2.cpyrhtDivCd`: 이미지별 권리 유형을 보존하고 대표 사진 일치 시 출처 표시
- [ ] 무장애 여행 정보 `KorWithService2`: 별도 활용신청 후 이동·휠체어·화장실·시청각·영유아 편의 제공
- 기상청 단기예보: 야외 장소에만 도착 무렵 날씨 제공
- 전국주차장 표준데이터: 목적지 주차와 섞지 않고 `주변 공영주차장`으로 별도 제공
- TourAPI 신분류/법정동 코드로 점진 전환
- 변경 금지 이미지에는 크롭·필터·텍스트 오버레이를 적용하지 않는다.

## 7. 완료 기준

- 후보 핀 끝점과 좌표 간 시각 오차가 0~2dp 이내다.
- 지도 단일 핀만 보고도 장소 종류를 구분할 수 있다.
- 묶음을 한 번 누른 뒤 하단 목록에서 모든 구성원을 바로 선택할 수 있다.
- 동일 줌 왕복에서 묶음 구성과 정렬이 안정적이다.
- 지도 선택, 목록 선택, 상세, 하단 CTA가 같은 장소를 가리킨다.
- 미선택 화면에서 후보 2개 이상이 보이고, 선택 영역의 핵심 수치가 한눈에 구분된다.
- 정보가 적은 상세에는 가짜 설명이나 큰 빈 섹션이 나타나지 않는다.
- 기본 글자, 1.3배, 2.0배 글자 크기에서 주요 기능이 잘리지 않고 접근 가능하다.
- Android 단위 테스트, 린트, 릴리스 빌드, 실기기 Maestro 흐름을 모두 통과한다.
