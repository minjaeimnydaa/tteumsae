1. 지도/목록 조건부 교체를 제거해 **결과 화면 안에서는 지도와 목록을 계속 유지**한다.
   손잡이·버튼은 접힘/중간/펼침의 단일 시트 상태를 사용하고 상단·길 안내는 고정한다.
2. 단순 지도 보기에서 전체 경로를 강제로 다시 맞추던 요청을 제거했다. 전체 경로 맞춤은
   별도의 명시적 행동으로 남기고, 지도/목록 왕복 자체는 사용자가 본 지도 위치를 초기화하지 않는다.
3. 선택·추천·경고·화면 전환마다 두 번 실행되던 자동 스크롤을 명시적 핀/묶음 클릭 요청으로
   분리했다. 목록에서 읽거나 선택할 때는 현재 스크롤 위치를 우선 유지한다.
4. 묶음 목록을 여는 처리에서 선택 해제를 제거했다. 묶음 보기·전체 보기·지도 이동은 탐색 상태만

## 1. 이번에 바꾸려는 사용자 경험

### 주소로도 출발·도착 장소를 고른다

장소 이름뿐 아니라 도로명·지번 주소를 입력해 결과를 고를 수 있게 한다. 주소 결과는 상호명이
있는 장소와 혼동하지 않도록 주소임을 알아볼 수 있게 표시한다. 입력한 글자 자체가 아니라
사용자가 선택한 결과의 이름·주소·좌표가 경로 입력에 반영되어야 한다.

기존 장소명 검색과 강원 목적지 지원 범위 확인을 보존한다. 강원 밖 목적지를 주소 검색이라는
이유로 허용하지 않는다. 응답 지연·검색어 변경·빈 결과·일부 검색 공급 실패에서도 이전 검색
결과를 새 검색의 결과로 잘못 선택하지 않도록 확인한다. 주소 검색 서버의 운영 검증은 위 기록을
따른다. Android의 정규 도로명 주소 선택은 실제 확인했으며 지번 단독·비지원 목적지 등 전체
주소 경계를 그 한 사례의 통과로 확대하지 않는다.

### 지도 위의 목록 높이만 바꾼다

지도 화면과 목록 화면을 교체하지 않고 **같은 지도 위에서 하나의 목록 시트**를 조절한다.
상단 뒤로·재확인과 하단 길 안내는 시트 바깥의 고정 영역에 둔다.

| 시트 상태 | 사용 목적 | 유지할 내용 |
|---|---|---|
| 접힘 / 지도 중심 | 경로·핀 위치를 넓게 확인 | 손잡이와 목록 요약, 다시 펼치는 행동 |
| 중간 / 지도와 목록 | 위치를 보며 후보 비교하는 기본 상태 | 보이는 지도와 실제로 읽고 누를 수 있는 카드 |
| 펼침 / 목록 중심 | 상세 시간·알림·다른 후보를 스크롤 | 고정 상단·길 안내, 손잡이, 같은 목록 위치 |

버튼과 드래그는 같은 상태를 변경한다. 시트 높이를 바꿨는데 버튼 문구나 실제 위치가 따로
움직이는 예전 문제를 되풀이하지 않는다. 지도↔목록 왕복은 전체 경로 재맞춤 요청이 아니다.

### 선택 버튼의 위치와 의미를 고정한다

선택 전 텍스트가 다른 위치의 작은 체크 원으로 바뀌던 표현을 같은 행동 영역 안에서 정리한다.
선택 전·선택됨·선택 해제 가능 여부를 색상만으로 전달하지 않고 문구와 상태로 구분한다.
장소명, 시간 지표, 상세보기의 기준 위치도 불필요하게 밀리지 않도록 한다.

카드 선택과 상세보기·알림 스위치가 한 번의 탭에 함께 실행되지 않아야 한다. 같은 장소를
다시 선택하면 해제하고 다른 장소를 선택하면 교체하는 기존 한 곳 선택 계약은 유지한다.

## 2. 코드에서 확인한 원인과 주의점

아래는 보완 착수 당시 code33 구조를 읽은 원인 기록이다. code34의 보완 현황은 위 최신 기록을
따르며, 이 원인 기록이나 코드 검토 자체를 실기기 통과 증거로 사용하지 않는다.

1. **지도 재생성:** `ResultsScreen.kt`의 `if (showingMap)`이 `RouteMapCanvas`와 목록을
   교체한다. `KakaoMapSurface`는 composition에서 빠질 때 `MapView.finish()`를 호출한다.
   돌아오면 새 지도와 초기 카메라·약 1.2초의 준비 표시가 만들어진다. 같은 지도 유지가 원인 수정이다.
2. **왕복 시 강제 지도 이동:** 기존 지도 보기 버튼이 `overviewRequestId`를 증가시킨다.
   SDK 지도 유지에 성공하더라도 이를 남기면 사용자가 움직인 지도 대신 전체 경로로 돌아간다.
3. **왕복·재조회 시 목록 이동:** 기존 스크롤 Effect는 선택 ID 외에도 추천 객체·경고·지도 표시
   상태를 관찰하고 360ms 간격으로 두 번 선택 카드에 이동한다. 명시적인 핀 클릭에 의한 카드
   노출과 단순 목록 재표시를 분리한다. 행 키는 장소 ID로 유지하고 실제 헤더/경고 유무로 인덱스를 계산한다.
4. **묶음 탐색과 여행 선택 혼합:** 기존 묶음 클릭 처리에는 선택 장소가 묶음 밖이면 선택을
   해제하는 코드가 있다. 상위 `onClearSelection`은 예약 알림도 취소한다. 묶음 보기·전체 보기·
   지도 이동은 탐색 상태만 바꾸고 선택 장소와 알림은 변경하지 않아야 한다.
5. **가려진 지도 영역:** SDK `setPadding`은 단순한 장식 여백이 아니다. 패딩을 제외한 영역의
   중심이 카메라 중심이며 공식 로고 위치도 영향을 받는다. 펼친 시트 전체 높이를 그대로 넣지
   않고 유효 지도 영역을 남긴다. 보완 전 결과 지도는 후보가 있으면 상단 128dp·좌우 72dp를 사용했으므로
   하단 여백만 화면보다 작다고 충분하지 않다. 작은 높이에서는 상단+하단 합도 확인한다.
6. **상세 왕복은 별도 수명:** 상위 `when (screen)`의 RESULTS→DETAIL은 결과 화면 자체를
   제거한다. 결과 안에서 지도·목록을 계속 유지하는 것만으로 상세 뒤로 복귀까지 카메라·목록 위치가
   보존되지는 않는다. code34는 시트·목록·묶음의 저장 상태를 추가했지만 카메라 복원은 하지 않는다.
   이 보존 범위와 실제 복귀 화면을 실기기 기록에 구분한다.

지도 패딩의 의미는 [KakaoMap 공식 SDK 문서](https://apis.map.kakao.com/android_v2/reference/com/kakao/vectormap/KakaoMap.html)를
확인했다. 현재 자동 전체 경로 맞춤 Effect의 의존성에 padding은 없다. 따라서 “패딩 변경이 기존
fit Effect를 매번 실행한다”는 진단은 하지 않는다. 패딩 자체의 중심·로고 변화와 별도로 검증한다.

주요 확인 파일:

- `android/app/src/main/java/com/tteumsae/app/ui/route/ResultsScreen.kt`
- `android/app/src/main/java/com/tteumsae/app/ui/route/RouteMap.kt`
- `android/app/src/main/java/com/tteumsae/app/ui/route/RouteResultComponents.kt`
- `android/app/src/main/java/com/tteumsae/app/ui/route/RouteFlowViewModel.kt`
- `android/app/src/main/java/com/tteumsae/app/ui/TteumsaeApp.kt`

## 3. 구현 시 보존할 상태와 책임

- 경로 입력·선택 장소·추천·계산시각은 기존 ViewModel이 소유한다. 시트용 복제 선택값을 만들지 않는다.
- 시트 위치·묶음 범위·목록 위치·핀 클릭에 따른 카드 노출 요청은 결과의 표시 상태다.
  표시 상태를 바꿀 때 검색·경로 재계산·알림 재예약을 함께 실행하지 않는다.
- 지도와 목록은 단순 시트 전환 동안 같은 composition과 인스턴스를 유지한다.
  보이지 않는 목록이 지도 탭을 가로채거나 접근성 탐색에 중복 노출되지 않는지도 확인한다.
- 사용자가 목록에서 카드를 선택하면 현재 읽는 위치를 우선 유지한다. 지도 핀에서 새 장소를
  선택했을 때만 중간 시트를 보여주고 해당 카드로 이동한다. 연속 핀 클릭은 마지막 요청을 따른다.
- 묶음 보기에서 후보 집합이 바뀌거나 재조회로 후보가 사라지면 범위를 안전하게 정리한다.
  기존 선택이 보이는 묶음 밖에 있더라도 탐색만으로 선택·알림을 해제하지 않는다.
  단, 새 추천에서 실제 선택 장소가 사라지거나 만료된 경우 기존 ViewModel·알림 조정 정책은 유지한다.
- 현재 지도는 한 곳 선택 뒤 다른 후보 핀을 숨기는 구조다. 이번 보완을 모든 대안 핀이 항상 보이는
  새 기능으로 설명하지 않는다. 묶음 상태 정책은 지연 이벤트·재조회 경계까지 포함해 검증한다.
- 높이는 화면 전체가 아니라 고정 상단·하단을 제외한 실제 콘텐츠 공간에서 계산한다.
  손잡이/헤더 측정값, 큰 글자, 시스템 인셋을 반영하고 음수 높이·겹친 정지점·0 지도 영역을 막는다.
- 연속 드래그 중 SDK 카메라를 매 프레임 다시 맞추지 않는다. 시트 이동과 카메라 이동을 분리하고,
  필요한 패딩은 안정된 시트 상태와 가용 공간에 맞춘다. 접힘·중간에서 공식 카카오 로고를 확인한다.
- 지도 제스처는 지도에, 목록 스크롤은 목록에 전달한다. 손잡이 드래그와 목록 최상단에서의
  아래 방향 조작이 버튼 상태와 어긋나지 않아야 한다. 큰 글자의 카드 하단·알림까지 도달 가능해야 한다.
- 뒤로·새 검색은 기존 검색 종료/알림 해제 계약을 보존한다. 시트가 접히는 행동과 새 검색을
  시작하는 행동을 암묵적으로 섞지 않는다. 프로세스 종료 후 결과 payload가 없으면 기존처럼 입력으로 복귀한다.
- 길 안내와 알림 활성화 직전의 현재 시각 검증, 재조회 중 길 안내 차단, 출발 마감 경계는 그대로 둔다.

## 4. 검증 체크리스트 — 새 버전에서 별도 기록

아래는 **최종 대조용 체크리스트**다. 위 중간 자동 검증을 참조하되 최종 소스와 실기기 결과를
확정하기 전에는 일괄 완료로 표시하지 않는다. 이전 버전 화면으로 새 버전 실기기 통과를 대신하지 않는다.

### 자동 검증

- [ ] 주소 검색: 도로명·지번·기존 장소명, 중복·빈 값·잘못된 좌표, 일부 실패와 늦은 응답 처리.
- [ ] 주소 선택: 실제 선택 결과 좌표 전달, 강원 밖 목적지 제한 및 기존 지역 검증 유지.
- [ ] 시트: 세 정지점 순서·가용 높이 경계·측정 헤더 반영, 작은 높이와 큰 글자.
- [ ] 지도: 펼침 상태의 과도한 하단 패딩 방지, 상하 여백 합을 고려한 유효 영역.
- [ ] 선택 카드: 동일 선택 영역·문구·선택 접근성 상태, 카드/상세/알림 행동 분리.
- [ ] 핀 노출: 실제 경고 행 유무별 인덱스, 없는 ID·후보 변경·연속 선택의 안전 처리.
- [ ] 지도/목록 왕복과 묶음 탐색이 선택·알림·검색 요청을 바꾸지 않는 계약.
- [ ] 수동 기본 빌드와 자동 보존 빌드 회귀, lint, 서명 APK와 GPS 권한 부재 확인.

### 연결 실기기에서 반드시 볼 경계

- [ ] 도로명 주소 → 선택 → 결과, 지번 주소 → 선택 → 결과, 기존 관광지명 검색을 각각 확인한다.
  키보드의 완료·뒤로, 검색 중 글자 변경, 비지원 목적지 안내도 확인한다.
- [ ] 결과 첫 화면에서 지도와 읽을 수 있는 카드가 함께 보이고 상단·길 안내가 잘리지 않는다.
- [ ] 접힘↔중간↔펼침을 드래그와 버튼을 섞어 반복한다. 버튼 직후 반대 방향 드래그,
  빠른 반복 탭, 목록 중간·최하단에서 왕복해 상태 불일치와 지도 재로딩이 없는지 본다.
- [ ] 지도를 직접 이동·확대하고 목록을 중간까지 스크롤한 뒤 왕복한다. 동일 지도 범위와
  읽던 목록 위치를 유지한다. 선택하지 않았을 때와 선택했을 때 모두 확인한다.
- [ ] 실제 핀 탭으로 맞는 카드가 보이고 선택 경로·카드·길 안내 대상이 일치한다.
  지도 핀 두 개를 빠르게 누르거나 해제해 마지막 사용자 행동과 결과가 맞는지 본다.
- [ ] 실제 묶음 핀에서 후보 목록을 열고 전체 보기·지도 이동·시트 조작을 한다.
  이 탐색만으로 선택 장소·알림 상태가 바뀌지 않는다. 실제 묶음이 없는 샘플을 통과로 대체하지 않는다.
- [ ] 알림을 켠 선택 카드에서 시트 조작·상세 왕복·지도 이동 후 같은 장소의 스위치와 예약을 확인한다.
  새 검색·장소 교체·실제 만료에서 해제되는 기존 정책과 구분한다.
- [ ] 상세보기 → 뒤로에서 선택과 알림이 보존되고, 시트·스크롤·카메라가 어떻게 복귀하는지 기록한다.
  앱 밖 카카오맵 → 앱 복귀 뒤에도 재확인 및 만료 안내가 살아 있어야 한다.
- [ ] 빈 추천, 후보 1개, 긴 이름, 경고 추가/제거, 재조회 실패·성공·선택 후보 소실을 확인한다.
  마감이 지난 경로를 시트 전환으로 다시 유효하게 만들지 않는다.
- [ ] 작은 폭·큰 글자에서 손잡이, 카드 선택/상세, 알림과 고정 CTA에 도달한다.
  제스처 내비와 테스트 가능한 시스템 내비 방식, 화면 회전/접기 조건은 실제 확인 범위를 명시한다.
- [ ] 지도 노출 상태의 카카오 로고·핀·경로가 가려지지 않고 지도 핀 탭이 시트에 막히지 않는다.

계정 삭제·로그아웃·기기 데이터 초기화는 검증 편의를 위해 수행하지 않는다. 화면·알림·로그에서
계정 정보가 드러나는 증거는 내부 QA로만 보관한다. 공모전·스토어에는 실제 관광지 예시의
완료된 화면만 사용하며 테스트를 위한 가짜 추천·합성 지도·잘못 선택된 장소 캡처는 넣지 않는다.

## 5. 새 후보 확정 후 인계

담당자는 실제 테스트 수·실기기 결과·미검증 경계·최종 버전·APK 해시를 QA/출시 기록에 남긴다.
새 버전을 채택하면 다운로드 안내, 원스토어 후보 APK, 권리 문서의 버전 설명 및 팀 공유 묶음을
대조한다. 주소 검색·결과 UI가 달라지므로 기존 code31/32 관광 캡처를 새 UI 촬영으로 표시하지 않는다.
최종 제출 자료 교체 여부는 팀 검토에서 판단하고, 원스토어 신청은 별도의 새 사용자 지시를 따른다.
