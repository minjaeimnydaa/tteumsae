# 수동 출발지 출시와 자동 위치 복구 구조

기준일: 2026-09-13. 이 문서는 기술 구조와 복구 절차를 설명한다.
신고 면제 판정, 서류 접수, 원스토어 심사 통과를 증명하는 문서가 아니다.

## 확정 범위

이번 기본 배포본은 사용자가 검색 결과에서 출발지와 목적지를 고르는 여행 계획 도구다.
선택한 출발지부터 계산하며, 사용자가 그 장소에 실제로 있다는 사실을 확인하지 않는다.
기존 GPS 코드는 삭제하지 않고 별도 컴파일 소스로 보존한다.

| 책임 | 수동 기본값 | 향후 자동 빌드 |
|---|---|---|
| 빌드 옵션 | `-PlocationMode=manual` 또는 생략 | `-PlocationMode=automatic` |
| 좌표 취득 공급자 | `src/locationManual`의 비활성 공급자 | `src/locationAutomatic`의 기존 GPS 구현 |
| 위치 권한 | 전경·백그라운드 위치 권한 제거 | 기존 전경 coarse/fine만 선언 |
| 사용자 입력 | 장소 검색·선택 | 검색·선택 및 기존 현재 위치 기능 |
| 상태 식별자 | `manual_v1` | `automatic_v1` |

잘못된 옵션은 빌드 단계에서 실패한다. `LocationAccessPolicy`는 같은 빌드 설정에서
읽으며 서버, 원격 설정, 사용자 숨김 메뉴로 변경할 수 없다. 기존 Gradle 작업 이름은 유지한다.

## 유지하는 기능

- 검색어 기반 출발지·목적지 검색과 목적지 지원 지역 확인
- 차량 경로, 경유지 추천, 도착 마감, 최대 체류시간과 계산 시각 기준 안내
- 지도·카테고리 핀·후보 비교, 상세 정보, 주변 주차·날씨·접근성 안내
- 기기 내 장소 저장, 선택 로그인, 새로 설정한 출발 알림, 카카오맵 연결

검색은 원래 검색어만 서버로 보내므로 GPS 검색 편향을 제거하는 추가 손실은 없다.
장소 상세의 날씨·주차 정보는 해당 장소 좌표를 사용한다. 수동이어도 선택 장소의 좌표는
서버와 지도·경로 제공자에게 전달되므로 '좌표를 전혀 처리하지 않는다'고 설명하지 않는다.

## 이전 경로와 알림

이전 GPS 출발점은 역지오코딩 뒤 주소 이름으로 바뀔 수 있어 '현재 위치' 문자열만 검사하면 안 된다.
`RouteFlowViewModel`은 모드가 없거나 현재 모드와 다른 복원 입력의 경로 키만 지운다.
같은 모드의 새로운 입력은 프로세스 재생성 후 복원하며 계정·찜 저장소를 변경하지 않는다.

알림 저장은 schema 2와 모드·무작위 토큰을 사용한다. 이전/다른 모드 snapshot은 복원하지 않는다.
앱 시작·부팅·업데이트에서 이전 알림 예약·표시와 외부 경로 PendingIntent를 정리한다.
새 알림의 클릭은 외부 URL을 직접 담지 않고 내부 Activity에서 현재 저장된 여행의 모드,
토큰과 유효시간을 검사한 뒤 길 안내를 연다. 이전 알림은 다시 설정해야 한다.

## 자동 위치 복구 절차

1. 실제 서비스 범위에 필요한 신고·증빙, 사용자 동의와 공개 정책을 준비한다.
2. `locationMode=automatic`으로 새 버전을 빌드하고 버전 코드를 올린다.
3. 자동/수동 공급자 검증, 권한 거부 대체 입력, 지도·알림·복원 실기기 회귀를 진행한다.
4. 원스토어 수집정보·설명·필요 서류를 실제 자동 동작에 맞게 갱신하고 변경 검증을 받는다.
5. 검증된 자동 버전을 공개한다. 심사 후 원격으로 숨겨둔 기능을 켜는 방식은 사용하지 않는다.

cd C:\dev\tteumsae\android

최종 수동 APK를 별도 파일명으로 복사하고 버전·SHA-256·실제 패키지 권한을 확인한다.
